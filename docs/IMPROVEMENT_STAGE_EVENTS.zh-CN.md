# 改进阶段的文件事件接力

`scripts/watch-improvements.ps1` 在指定协作目录内接收文件事件。显式提供
`-RosterFile` 时，提案推进、租约释放、验证回执完成都会重新检查接力资格，
不需要再投递一个 inbox 事件，也不需要等待下一次 60 秒恢复扫描。

```powershell
pwsh.exe -NoProfile -File .\scripts\watch-improvements.ps1 `
  -Python <已安装当前 AEP 的 python.exe> -CoordRoot <协作目录> `
  -RosterFile <已核实成员名单.json>
```

监听器注册完成后才执行初次恢复，避免扫描与注册之间的窗口。新目录也预先创建，
后续新提案无需重启。事件经过 200 毫秒合并，再调用现有 CLI：

| 来源 | 精确范围 | 动作 |
| --- | --- | --- |
| 信箱 | `improvement_spool/inbox/*.json`、`.stop` | drain 后检查调度；停止标记优先退出 |
| 提案阶段 | `improvements/<24位ID>/<6位序号>.json` | 检查当前阶段和接力资格 |
| 验证记录 | `improvements/<ID>/runs/<32位运行ID>/request.json`、`receipt.json`、`recovery.json` | 检查运行是否仍阻止接力 |
| 认领 | `improvement_claims/<24位ID>.json` | 检查认领、释放和完成状态 |

创建、重命名、修改、删除都会检查对应的正式文件名。事件本身没有授权含义，
CLI 仍会读取真实日志、认领和回执，并检查候选成员。相同日志头继续使用稳定事件 ID，
重复通知不会重复排队。每轮至多排队一项，保留既有保守容量与未知送达处理规则。

未提供 `-RosterFile` 时仅监听信箱并接入提案。提供名单也只向既有 commander 信箱排队，
不会启动测试、调用模型、发送桌面输入、创建会话或部署。presence 与能力名单是声明，
不等于真实 Agent ACK 或身份认证。

测试输出、报告、临时发布文件、锁文件、spool 回执和 commander 自身输出不会触发调度。
这避免排队写入引发无限循环。阶段事件只检查调度，不重复 drain 信箱。
通知溢出触发本地恢复；每 60 秒的恢复仍保留，补偿丢失事件、租约自然到期等变化，
不调用模型或网络 API。presence、roster、campaign 和 commander 收据的单独变化目前依赖
后续被监听事件或恢复扫描；此版本没有订阅这些来源。

200 毫秒合并不是写入重试机制。任何 drain 或 schedule 错误，包括发布者仍持有写锁，
都明确报错并停止；不会等待解锁后偷偷重放可能已部分完成的操作。需先核对回执与订单，
再显式决定恢复。监听器 OS 独占锁和保留 `.stop` 的行为不变；停止只结束监听进程，
不会终止其他执行、撤销排队订单或撤回消息。

测试或宿主可选用 `-ReadyFile <不存在的文件路径>`。它在初次恢复成功后以独占创建写入
`status=READY`、PID、协作目录和时间。父目录必须存在，文件应放在监听输入目录之外。
已有文件、缺失父目录和监听输入目录内的路径均在恢复前拒绝；进程退出后文件保留，
只证明该次启动曾就绪，不是实时健康状态或 ACK。
`-Once` 同样支持此握手。生产环境没有因此自动启动或安装监听器。

`tests/test_improvement_stage_watcher.py` 使用真正的 Windows PowerShell 7 子进程与隔离临时目录，
分别验证阶段推进、认领释放、验证回执完成在没有新信箱消息时及时排队，重复事件去重，
输出/临时文件不触发调度，以及信箱/调度写锁冲突明确停止而不重试。另检查启动后新提案
目录、READY 路径预检及单实例互斥。成员在线状态与能力名单均为
明确标记的测试夹具；验证回执测试也使用合成的旧版结果，不声称实际运行了验证子进程。
