# 红皇后—鲶鱼—创造性破坏体系：协同推理与行动工作流 v1.0

日期：2026-10-15。性质：理念与设计规范；不能据此推断全部运行功能已经实现。

本文是[红皇后—鲶鱼—创造性破坏总体系](SYSTEM_OVERVIEW.zh-CN.md)的工作流分册。总体系保持不变：外部竞争驱动持续校准，内部挑战保护异路，实证择优推动可逆替换。本文把这三种动力展开为日常推理与行动步骤。

来源：用户提出的 16 条协同推理方法，以及本轮方法论、反同质化、模拟用户代表三个独立 subagent 的审议。用户代表包含新手、忙碌委托人、领域专家与维护者，属于模拟需求推演，并非真实用户访谈。

## 一、目的与基本主张

让多个 Agent 在真实任务上比单个 Agent 做得更好，同时减少人的重复交代、纠错与协调负担。多模型、多角色、多轮次都是实现目标的手段，采用多少取决于任务收益。

核心原则：保留独立探索，交换可检验主张，用证据裁决分歧，以实际结果评价协作。允许观点竞争，要求证据协作，保留可恢复的异议。

“自动进化”在此指任务流程、工具、策略和记忆在验证后的迭代；不意味着模型权重已自训练，也不意味着系统具备无限权限或保证解决任意问题。

## 二、五层概念结构

| 层 | 解决的问题 | 最小产物 |
| --- | --- | --- |
| 目标与契约 | 什么算完成，允许付出多少 | 任务契约、验收标准、授权和预算 |
| 独立探索 | 哪些不同方法值得尝试 | 独立初稿、方法差异、可证伪预测 |
| 交互与制衡 | 谁质疑什么，分歧如何解决 | 主张账本、争议清单、反例、利益关系 |
| 证据与裁决 | 凭什么选择方案 | 原始来源、实验、独立复现、裁决理由 |
| 行动与进化 | 谁执行，失败如何恢复 | 负责人、工件、验收、回滚、复盘与机制提案 |

默认主循环：任务契约 → 选择协作规模 → 独立探索并冻结 → 定位分歧 → 最小判别实验 → 选择与集成 → 执行验收 → 复盘。达到标准即可交付；出现新证据可重新开启。

## 三、对原始 16 条的完善

| 原始方法 | 保留价值 | 增补规则 |
| --- | --- | --- |
| 1 专家人格拆分 | 快速扩大提问和风险视角 | 同一模型多人格只算相关意见，不能充当多个独立裁判 |
| 2 多模型汇聚再分发 | 发现并修补不同方案的短板 | 首答独立冻结；先分发差异、证据与争议，全文按需读取；保留一个盲审者 |
| 3 提示词重构 | 消除歧义、建立机器可读契约 | 保留原始问题；改写记录版本，核对目标、约束、单位和验收标准等价 |
| 4 轮次交叉批判 | 发现作者盲点 | 按主张分配审阅；批评要给反例或判别实验；无新信息时终止该轮 |
| 5 多语言交叉 | 检查语义稳定性、探索不同表述 | 回译与约束核对；差异本身不增加事实可信度 |
| 6 地域视角 | 探索不同使用环境和需求 | 明确法规、成本、设备与用户变量；人设不等于真实地理位置或当地事实 |
| 7 僵局换模型或交接 | 引入缺少的能力，恢复长程任务 | 先分类分歧；新模型盲审原始证据；交接保留失败、异议和下一项实验 |
| 8 交互式决策 | 用户能纠偏和选择取舍 | 陪伴式、检查点式、委托式三种模式；已授权可逆步骤自主推进 |
| 9 渐进式引导 | 控制任务粒度和依赖 | 顶层契约保持完整；当前只激活少量可执行子任务，避免逐步拆解丢掉全局目标 |
| 10 结论交叉核验 | 找到一致与冲突 | 共识是检查线索；共同信息源只算一个来源，外部证据与独立复现另记 |
| 11 对抗模板 | 主动制造替代假设 | 模板绑定攻击面、可证伪条件与预算；避免只挑喜欢的回答 |
| 12 动态复盘 | 记录状态变化、支持恢复 | 在关键事件或阶段门生成增量摘要；记录事实、决策、异议、失败与待办 |
| 13 深挖细节 | 解决关键未知 | 每次追问对应未决主张或决策；证据不足时允许保留未知 |
| 14 主线管控 | 保持目标与责任明确 | 每个子任务绑定验收项；设负责人、代理人、依赖与取消条件 |
| 15 循环采集 | 感知外部变化 | 优先事件；必要时由轻量程序定时检测变化，去重、检查时效后再唤醒模型 |
| 16 多 Agent 互评 | 并行与互补 | 增加能力发现、领取/租约、ACK、断点、独立性登记和成果验收 |

## 四、任务契约与独立性

任务开始至少记录：原始目标、成功标准、必要约束、允许操作、资源预算、截止或检查点、负责人、交付物、停止及重启条件。未知字段可显式记为待确认；不会影响推进的缺项不应让任务停摆。

独立性分三个维度分别登记：观点是否先独立形成、方法是否不同、数据与复现过程是否独立。同模型、多模型、不同窗口、不同语言均不能单独证明证据独立。接触过他人方案的后续结论应标记为共享后结论，保留原始首答供比较。

关键主张至少区分事实、假设、推断、偏好和决定；记录来源、适用范围、支持/反对证据、验证状态、责任人及什么观察会改变结论。保存可审计的理由摘要和操作证据，不要求暴露模型私有内部思维过程。

## 五、分歧处理与多角色鲶鱼

事实冲突查原始证据；实现路线冲突做同预算实验；目标和价值取舍交委托人选择；证据不足记为未知并提出最便宜的下一项验证。多数票可以表达偏好，事实判断依赖证据。

鲶鱼是多个攻击面的职责，可由可用成员轮换承担：设想者提出结构性异路；反证者设计判别实验；复现者独立重跑；偏差审计者检查挑结果、改指标和遗漏；裁判审计者复核评分标准；诚信守门员核对发布措辞。职责分离按风险启用，完整审议链按既有五角色契约执行，缺员就记录缺口。

争议回合的最小产物是“争议主张、竞争解释、能区分解释的观察、实验预算、止损条件”。没有这些产物的辩论不能持续占用主线资源。最终结论保留重要少数意见、反例与重启触发条件。

## 六、协作规模、用户体验与恢复

| 模式 | 默认流程 | 升级依据 |
| --- | --- | --- |
| 轻量 | 单执行者与必要的一次自检/复核 | 明确可逆、低不确定性 |
| 标准 | 独立方案、针对性质疑、执行验证 | 有多条可行路线或明显专业短板 |
| 攻坚 | 主线负责人、多路径实验、独立反证复现、有限轮次裁决 | 高价值、高试错成本、重复失败或跨域依赖 |

用户只需给自然语言目标，协调者负责建议适当模式。人工参与有三种选择：陪伴式频繁互动，检查点式在关键取舍互动，委托式在授权和预算内自主推进。仅有角色、技能或 MCP 可用不代表任务已被授权；接入后记录实际能力和验证证据。

上下文分为稳定偏好、项目事实、当前任务状态和原始可见记录。短消息传事件 ID 与摘要，全文保存在本地可查；读取时保持来源与指令权限，不把网页、历史日志和他人转述自动当作当前用户命令。默认保持原会话；确需交接时提供目标、已证事实、失败实验、异议、工件哈希、未知项和下一行动。

投递、可见、ACK、执行、完成、验收分别记录。心跳丢失触发状态确认和有条件的接力；不明结果的写操作先核查再恢复。无人值守时按事件和检查点唤醒，静默状态不调用模型做无变化轮询。

交付采用两层：默认展示结果、证据强度、未决问题和下一步；展开可查来源、实验、异议和决策记录。忙碌用户不必阅读全部讨论，领域专家仍可审计关键依据。

## 七、停止、激励与自我进化

达到验收标准时交付；连续回合没有新增证据或可行路径时转最小实验或暂停该争议；预算到限、关键依赖缺失时输出阻塞和可恢复状态。同类失败无新修复证据时停止消耗正式额度。每项探索预先声明预算，不用固定轮数制造无意义讨论。

AP 奖励经核验的探索贡献，RP 奖励纠错与避免损失，长期声誉随可靠行为慢变。诚实撤回、有效负结果和失败经验可以贡献；发言数量、赞同数量、包数量或反复复用证据不能作为进步指标。评分标准也接受独立审计，分数不自动赋予权限。

进化按“观察缺口→冻结基线→提出可逆改动→旁路实验→独立审议→明确采纳→监测回退”推进。保护历史失败库和异路候选，以免只学习近期胜者。自动修改的范围与授权、回滚和验收绑定；当前 AEP 的门禁和角色模块只是这条闭环的部分实现。

## 八、怎样证明 1+1 大于 2

用同类任务、相同工具条件与可比资源，对照最佳单 Agent 流程。比较成功率、错误逃逸率、可复现率、完成时间、费用、用户干预次数、重复交代次数、同错复发率、交接返工率和指令应用延迟。优先报告质量、时间和成本之间的实际取舍；若声称全方位优势，应有重复任务证据。

不以讨论热度、共识率、角色数或积分证明卓越。示例反例：五个模型引用同一篇错误资料，仍只有一个错误来源；中英文答案不同，可能是翻译改了约束；所有 Agent 读过首发答案后同意，可能只证明观点趋同。

## 九、本轮审议与迭代路线

方法论专家主张把独立性和可验证性放在中心；反同质化专家要求匿名比较、少数路线和裁判受审；模拟用户代表要求分级调用、关键节点交互、可恢复原会话和两层交付。三方均支持先独立后共享、用实验解决技术争议。

保留分歧：领域专家偏好充分展示依据，忙碌委托人偏好简短结果，以两层交付协调；用户可能希望所有成员持续活跃，维护者更重视事件触发和成本，应以任务覆盖率和响应延迟验收，而不以持续发言验收。

P0：统一任务契约、停止条件、权限/预算、主张类型与恢复包。P1：独立首答与差异分发、分歧实验、角色制衡、真实任务基线评估。P2：多语言/地域探索、历史对手池、裁判漂移审计、动态激励。每项后续实现单独记录代码、测试和实机验收状态。
