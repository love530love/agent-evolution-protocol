# v0.6.33 — 严格原会话证明进入发送活路径

## 解决的问题

此前 `session_attestation` 已能保存短期前置证明，但没有成为实际输入前的硬门。整窗文字或侧栏标题可能包含目标会话 marker，却无法证明当前正文和输入框属于那个会话。

v0.6.33 将可选的严格模式接入 profiled UIA 活路径。它不替代发送、可见性或 ACK 判定；它只在任何文字被键入前回答“这一刻是否仍是被登记的原会话”。

## 行为变化

- strict profile 要求 `session_region`、`model_region`、`selector_region`、`composer_region` 四个经校准的归一化区域；selector 不得与其他三块重叠。
- 严格 proof 要求：受限活动区中唯一会话 marker、受限模型区中唯一模型 marker、可信 exe/PID/标题/HWND/UIA runtime id，以及已登记且当前匹配的 session fingerprint。
- 若需要切换会话，只能点击受限 selector 区中唯一候选，并必须重新在活动区证明 marker；侧栏命中本身永不授权输入。
- composer 必须完全位于 composer 区。获得焦点后，驱动会再次读取活动会话和模型 marker；同一 HWND 内切换 chat、renderer runtime 变化或 surface 变化均在第一笔写入前拒发。
- 严格 UIA3 发送失败时不会降级到 OCR/PowerShell 输入。button 模式复用已经被证明的同一 wrapper，避免第二次窗口查找落到别的实例。

## 明确不声称的内容

- 未把示例或现存 Qoder/Qoder CN/WorkBuddy/WorkBuddy AI/CodeBuddy profile 自动切换到 strict；它们尚未带真实三/四区域标定。
- 未把 attestation 视为 `MESSAGE_VISIBLE`、ACK、结果读回或订单完成。
- 未取得本 release 新发起的第三方原会话
  `INPUT_SUBMITTED → MESSAGE_VISIBLE → AGENT_ACK → TASK_RESULT_READBACK` 实机闭环。
