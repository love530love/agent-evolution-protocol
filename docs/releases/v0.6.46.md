# v0.6.46 — 真实派工卡点固化为只读就绪诊断

## 本轮交付

2026-11-22 用户指出「不真实派工就永远不知道卡在哪里」。本轮把真实派工过程中手工排查出的
四个卡点，固化进既有只读预检模块 `coordination/delivery_preflight.py`，**不进投递活路径、
不新增 schema、不放宽任何判定**。

- **派工就绪诊断**（`--readiness`）：一条命令给出每个 agent 的 `action` /
  `blockers` / `may_dispatch`。`action` 取值 `NEED_PROFILE` /
  `FIX_SESSION_MARKER_CONFIG` / `FIX_DISPATCH_TEXT` / `REOBSERVE_FIRST` /
  `WAIT_OR_REOBSERVE` / `SEND_AFTER_VERIFICATION`。
- **四个真实卡点机器可判定**：
  - `dispatch_text_diagnosis` 检测正文 event id 数量/一致性、`AEP-ACK` 指令与任务标记；
    复用 `dispatch_gate.EVENT` / `TASK_MARKER` / `ACK_TOKEN` 同一正则与 token，不造第二套标准。
    真实案例：WorkBuddy AI 订单正文塞了自动 `EVT-` + 手写 `WAKE-` 两个 id，
    被 `one_event_id` 拦在输入之前（`DISPATCH_REFUSED`），看起来像「什么都没发生」。
  - `session_marker_diagnosis` 检测 profile 的 `session_marker` 配置漂移。
    真实案例：qoder 的 marker 误填为侧边栏按钮「请加入项目协作区」，会话内 `absent`，
    投递永远被会话闸门拒绝；诊断报 `SESSION_MARKER_CONFIG_DRIFT` 并给出会话内已可见的
    候选标记，但**不改配置、不放宽 `seen=True`、不写 profile**。
  - `observe_freshness` 用 `uia_receipts/last-<agent>.json` 的文件 mtime（默认 900 秒）
    判新鲜度。真实案例：qoder_cn 留着历史的「seen 可投」回执，但实际窗口早已不存在；
    陈旧回执一律 `REOBSERVE_FIRST` / `OBSERVE_STALE`。
  - 无已验收 profile 明确报 `ORIGINAL_SESSION_PROFILE_REQUIRED` / `NEED_PROFILE`，
    不把「能力缺失」误读成「没人在线」。
- **边界严守**：全部诊断恒 `advisory_only=true / ui_input_performed=false`；
  `may_dispatch` 只是只读就绪判断，不等于已送达、更不是 ACK。忙态插话另走
  `coord-uia deliver --urgent-interject`，不在诊断内执行。只有 `VERIFIED` 能关单。
- **能力卡与文档**：`skills/aep-delivery-preflight/SKILL.md` 增加第 5 步派工就绪诊断与
  `action` 判定表；`docs/DESKTOP_DELIVERY_PREFLIGHT.zh-CN.md` 第 10 节记录四个真实卡点、
  约束与复算命令。
- **测试**：`tests/test_delivery_preflight.py` 新增 `DispatchReadinessTests`（10 项），
  覆盖两个 event id、期望 id 不符、marker 漂移/修复、无 profile、陈旧 observe、
  CLI 只读性。守线复算 `test_delivery_preflight + test_dispatch_gate +
  test_uia_transcript_verdict` = 76 passed / 37 subtests；
  `test_delivery_preflight + test_capability_cards + test_skill_manifest` =
  72 passed / 241 subtests。
- **全量回归**（版本先钉 0.6.46，`CODEBUDDY_SAFE_DELETE_ENABLED=0`）：
  **1983 passed, 4 skipped, 1048 subtests passed, 269.95s, exit 0**。
  首轮曾遇 `test_campaign_watcher_integration` 的 watcher 30s ready 超时（环境时序 flaky，
  与本版改动无关），定向复跑 1 passed / 3.86s、随后全量复跑全绿，如实记录。

## 边界与未做

- 本版只做只读诊断；**没有**改 commander 活路径、没有新增 `coord-*` 命令、
  没有改 `cli.py` / `skill-manifest`、没有新增 schema 文件。
- 真正让 WorkBuddy / WorkBuddy AI 获得桌面真发能力，需要为它们标定并验收
  UI profile（当前无 UIA 树、OCR lump 无法锚定会话）——本版仅明确报出该缺口。
- qoder 会话标记修复是运行时配置（`coordination/ui_profiles/qoder.json`，gitignore），
  不进代码提交；本版把它变成可复算诊断，避免同类漂移再次静默发生。
