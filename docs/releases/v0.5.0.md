# v0.5.0｜持久联邦工作区、派工信箱与心跳驱动

## 主要变化

### 持久联邦工作区（心脏）

- 新增 `federation/` 包：事件账本（哈希链 + `prev_sha256` + `event_id`/`parent_event_id`）、
  三区快照（`anchored_request` / `dag` / `artifacts`）、接管包、故障诊断表、策略进化库；
- 工作区级排他锁：跨进程互斥、进程内可重入，POSIX 用 `flock`、Windows 用 `msvcrt.locking`；
  无锁对照实验 400/800，加锁后 800/800；
- 真实跨进程 A2A 适配器（JSON-RPC over stdio）+ 4 个真实子进程的演示，
  其中两个在中途崩溃/耗尽上下文，任务被自动转交。

### 派工信箱：消息即任务（`coord-assign`）

- 一次调用写三件事：DAG 节点、写租约、可执行派工单；
- 派工单正文含 ACK 行、`coord-claim`、`coord-task-state --phase working/done`、租约续期命令；
- scope 冲突如实返回 `claim: scope_conflict`，不假装成功。

### 心跳驱动（`federate step` / `federate serve`）

- 一步固定顺序：**先结案 → 再排程 → 再认领 → 最后真发**，同一 tick 内接力下游节点；
- 结案只认执行者自己写的 `coord-task-state`，沉默不算成功；
- `engine.fail_task` 让"看得见交付已死"的调度者立刻换人，不必干等心跳超时；
  `_tick` 与 `fail_task` 共用同一张决策表，一个信号只映射一个动作。

### 一次输入驱动全队（`federate intake`）

- `--shape single|reviewed`；`reviewed` 的复核节点交给**另一个** agent，
  `preferred` 只重排有能力的候选，不会把无能力者提上来；
- 隔离目录实测两跳闭环：`execute → done` 同时 `review → running`，第二步 `review → done`。

### 桌面执行（手）

- 修复中文参数被控制台代码页（ibm437）吞成 `?` 的真缺陷：非 ASCII 值改走 UTF-8
  `-ParamFile`，脚本在参数绑定后覆盖；脚本 stdout 固定 UTF-8，回执不再乱码；
- OCR 引擎语言可指定并写进回执（`ocr_language`）；此前静默使用 en-US，
  中文界面被读成拉丁近似物而不报错；
- 紧急插话只在 profile 精确声明插话控件时进入，**绝不点停止/取消**；
  `send_mode` 支持 `enter`/`button`/`auto`；
- Qoder 与 Qoder CN 拆分为两个客户端，避免跨客户端误匹配。

### 语义修正

- `requirement` 不再兼任能力键，改用 `capability`（缺省回退，老工作区不受影响）；
- `claim` 支持租约 TTL，过期不再永久阻塞；同一 agent 跨任务覆盖同一路径记为
  `self_overlaps` 而非冲突；
- `coord-claim` 走写侧闸门，被拒绝时不留半截 owner 记录。

## 已知阻断（未达成，不写成"已支持"）

桌面 `INPUT_SUBMITTED` 及之后仍未达成：本机未安装中文 OCR 识别器，
回执显示 `ocr_language: en-US`（即使请求 `zh-Hans-CN`），因此中文会话标记与输入框提示无法匹配。
需要管理员执行：

```powershell
Add-WindowsCapability -Online -Name "Language.OCR~~~zh-CN~0.0.1.0"
```

详见 `docs/HANDS_AND_FEET_STATUS_20261031.zh-CN.md`。
