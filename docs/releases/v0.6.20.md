# v0.6.20 — 居中协调愿景的事实基线：先证伪，再立项

本版**只加一份文档**，不改动任何运行时代码。它回答的是操作员提出的一个大方向：
能否把项目演化成「居中调动所有 Agent、代替人类工程师完成长程任务协调」的协调器，
并引入开源能力让手脚更健壮、把各 Agent 有限额度用足、避免团队被错误情报带偏。

这份文档的作用不是宣布设计完成，而是**先把愿景拆成可复算的断言，逐条标注证据状态**。
操作员本人给了一条硬要求：「有些观点需要实据，避免团队受错误情报影响而越来越差劲」——
在一个以证据链为核心的项目里，协调器自己不能先靠未经核验的断言立项。

## 1. 八条断言，只有四条部分站得住

| 断言 | 证据状态 |
|---|---|
| 自动化 / 定时 / 按估算时长轮询与插话 | 部分：轮询与插话有实测代码，「按估算时长」无实现 |
| 独立居中协调长任务 Agent | 无：CLI 无 mission 子命令、无 runner、无自启动器 |
| 引入开源能力 | 可行但受硬约束（见第 4 节） |
| 居中完成分工、传递、唤醒、回表 | 部分：各有实现，但彼此未接线、无统一一拍 |
| 代替人类工程师 | **不成立**（见 3.3） |
| 调动存活或可启动的 Agent | 部分：登记与唤醒可用，但启动 ≠ 接单 |
| 极致调额度、省积分 | **没有数据支撑**（见 3.1） |
| 避免偏听偏信 | 字段级有、核验级没有（见 3.2） |

## 2. 三态能力矩阵

**已实测跑通**：`commander` 订单状态机、`federation` engine/supervisor 的 tick/lease/stalled/
recover、`claim_conflicts`、`session_fingerprint`、`action_verification`、`delivery_audit`、
`trajectory`、`campaign_cycle` 回表与 ACK 截止、`hold_alerts`、`wake_daemon --once`、
事件驱动的 `campaign-watch.ps1`、v0.6.16 实测的桌面唤醒与 Qoder 插话、v0.6.19 的 `mission_pulse`。

**有代码有单测、但没有消费者**：`mission_planner` / `mission_runtime` / `mission_graph` /
`mission_supervisor.inspect`（只返回建议）、`artifact_manifest.verify`、`resilience_scenarios`、
`recovery_policy.decide`、`insight_miner`、`joint_attack`（五角色对抗 + 哈希链）、
`quorum.evaluate`（N-of-M + 证据哈希 + 禁自批）、`legion_ledger`、`volley_plan`、
`transcript_bus`、`command_memory.announce()`（注释明写 "Mailbox delivery is not read or ACK"）。
最典型的一处断口：`engine.complete()` 收 `artifact_path` 却不调近在旁边的 `artifact_manifest.verify()`。

**完全没有**：per-Agent 积分额度 / 用量 / 重置间隔 / 限流 / 成本记账；统一 `broadcast` /
`notify_all` 与「通报全队 → 催促查看回表」接线；消息来源可信度自动核验；
「共同来源只算一个来源」的自动判定；持久化调度游标；跨重启 mission 恢复；
artifact 验收接线；通知定级策略；mission runner 与 CLI `mission*` 子命令。

**只在文档里**：7x24 无人值守、`COLLABORATIVE_REASONING_FRAMEWORK` 的 P0/P1/P2 路线、
delegation playbook。「每 15 分钟续租」也只是 `assignment.render` 写进派工文本的一句话。

## 3. 三个必须先证伪的断言

### 3.1 「省积分」目前算不出来
`legion_ledger.py` 是贡献评分账本（注释：not transferable credits / grants no operational
authority），`cli.py` 的 `budget_*` 是单轮赛制预算，`volley_plan.plan()` 带
`PROPOSAL_ONLY_NOT_AUTHORIZED`，`reasoning_contract.budget` 只是 planning data，
CHANGELOG 自述没有 quota 调度。要谈「极致调动额度」，至少要有每个 Agent 的额度、已用量、
重置时刻、单次任务成本估计这四类事实 —— **一个都没有**。第一步不是优化，是**记账**。

### 3.2 「避免偏听偏信」靠字段，不靠核验
`THREAT_FIELDS`（`source / observed_at / freshness_ttl / confidence /
cheapest_confirmation / response_deadline`）与 `DECISION_FIELDS` 存在，但
`governance_event()` 只校验字段齐全与 `confidence` 枚举，不核验内容；`quorum.evaluate()`
与 `joint_attack` 的交叉验证没接进派工路径；协同推理框架文档自己写了
「五个模型引用同一篇错误资料，仍只有一个错误来源」，却没有自动判定。

**本次检索抓到的现成反例**：某中文技术博客把 MCP 全称写成
"Multi-agent Coordination Protocol"，附会任务拍卖、区块链贡献记录与 PBFT 共识；
官方 `modelcontextprotocol.io`（规范 2026-07-28）定义是 **Model Context Protocol**，
把 AI 应用连到外部系统（数据源、工具、工作流）的开放标准，类比「AI 应用的 USB-C」。
把它当事实喂给团队，转述一百次也不会变成两个独立证据。该博客**仅作为反例引用**。

### 3.3 「代替人类工程师」现阶段不成立
v0.6.19 边界：没有注册任何 OS 计划任务、没有常驻进程、没有跨重启恢复演练、
不承诺 7x24 无人值守；OS 计划任务还需登录会话。本机由 agent 内部 spawn 的常驻进程
会被作业对象回收，`CREATE_BREAKAWAY_FROM_JOB` 不被允许。关单仍需 `VERIFIED`，
`improvement` 链要求 reviewer≠author 且 `PROPOSED` 不自动晋升。
准确说法是「**有证据的协调副驾**」，不是替代者。

## 4. 开源能力：引协议，不引运行时

| 项目 | 官方事实（2026-11-05 取回） | 结论 |
|---|---|---|
| MCP | Model Context Protocol，AI 应用 ↔ 外部系统标准，规范 2026-07-28 | 可把唤醒/读表/回表标准化为外部工具；不管多 Agent 协调，不必重写既有 UIA/OCR |
| A2A | Agent2Agent，Google 捐 Linux Foundation，Apache-2.0；官方明确不是 agent 开发套件、不管子 agent/工具调用、不是消息应用 | 可借 Agent Card 与委派消息格式；但项目已有三套 envelope schema，**再加第四套就是并存标准**，且 A2A 不提供 durable orchestration / quota / 证据核验 |
| Temporal | 自托管需 Temporal Service（Docker/K8s/手动）+ 持久化存储 + Worker；`server start-dev` 仍是常驻服务 | 借鉴 event-history 语义；与「不常驻、不占资源」冲突，不部署 |
| LiteLLM Proxy | `max_budget` / `budget_duration` / `budget_limits` / `model_max_budget` / `tpm_limit` / `rpm_limit` / `max_parallel_requests` / `spend` / `budget_reset_at`，窗口规则明确；官方明写 "Budgets require a database"、"none of them cap anything on a DB-less deployment" | 只借字段语义与窗口规则，在项目内做纯文件账本；不部署 Postgres + Proxy |

**准入四条硬约束**：① 库级可嵌入、无独立服务/DB/后台线程；② 不新增 schema 或 `coord-*`
命令面；③ 判断仍是规则、可复算、fail-closed，模型只做 advisory；④ 单次调用有界、
默认 dry-run、进程退出即结束，OS 触发归操作员。

## 5. 分期路线（每期带可复算验收）

- **P0 一拍接线**：一次性 `coordinator_tick`，按固定顺序调用既有单步，默认 dry-run，
  统一回执；**不新建调度器**，不改既有单步签名。
- **P1 额度可计算**：per-Agent quota ledger，先能回答「谁还有额度、何时重置」；
  无数据必须报 `NO_QUOTA_DATA` 而不是猜测。
- **P2 实据可核验**：claim↔evidence 绑定、共同来源去重、`quorum.evaluate` 接进派工路径。
- **P3 手脚标准化**：唤醒/插话/读表/回表做成可选 MCP tools 或 A2A Agent Card 描述，
  仅作对外接口，内部仍走既有桌面适配器。
- **P4 闭环**：`artifact_manifest.verify` 接线、通知定级、跨重启恢复、持久化调度游标。

## 6. 明确不做

不宣称「代替人类工程师」「7x24 完全无人值守」「已节省积分」；不启动常驻 watcher /
后台线程 / model server / Postgres / Proxy；不由 agent 注册 OS 计划任务；
不用概率模型做心跳、闸门或裁判；不把 `DEPOSITED` 写成送达；不用 `VERIFIED` 之外关单；
不加第四套 envelope schema，不建第二套调度器。
