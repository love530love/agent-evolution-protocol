# v0.6.11 — 上一版说了一句假话：「没发出去」

v0.6.10 把 ACK 判定统一成四道守卫，并让 `supervisor` 在「已发送但没有 ACK」时扣住任务。
两个机制都对。但它对 `CEASED` 的处理是错的，而**真实订单一眼就抓到了**。

## 缺陷

`ack_protocol.sent()` 只在 `INPUT_SUBMITTED` / `MESSAGE_VISIBLE` / `AGENT_ACK` 三个状态上返回真，
`CEASED` 一律算「没发」。可是 `commander` 在 `CEASED` 里写的是**两种相反的事实**：

```
DELIVERY_UNPROVEN: adapter failed; manual diagnosis required
SUBMISSION_UNCONFIRMED: possible send; do not retry automatically
```

前者是「适配器失败，什么都没打进去」，后者是「**可能已经发出去了**」。
把两者都判成 `not_sent`，等于用一句我们并不掌握的事实去替代「不知道」。

真实证据（2026-11-01，只读跑 `coordination/`）：

```
订单 2026-10-30T0422243473450000-04d70400   qoder / AEP-CI-FAIL-20261030
最后 6 次尝试的 note 全部是 SUBMISSION_UNCONFIRMED: possible send; do not retry automatically
v0.6.10 的 coord-ack 输出:  "state": "not_sent"          <- 假话
v0.6.11 的 coord-ack 输出:  "state": "submitted_unconfirmed",
                            "delivery": "unconfirmed"    <- 如实
```

## 修法

`state` 从三值变四值：

| `state` | 含义 |
|---|---|
| `acked` | 有通过四道守卫的回复 |
| `sent_unacked` | 证明打进去了，还没有 ACK |
| `submitted_unconfirmed` | **可能发过，无法确认**（新） |
| `not_sent` | 证明什么都没打进去 |

新增 `delivery(order)` → `proven` / `unconfirmed` / `none`，判定依据是尝试记录里的
`state` 与 note 前缀。`sent()` 仍然只在 `proven` 时为真，**这一点是刻意的**：
「可能发过」不能把任务钉在等一个也许从没被问过的回复上，但也不能被说成「没发」。
两个陈述各自为真，`supervisor` 的 hold 语义因此不变。

note 前缀用**前缀匹配**而不是整句相等，这样 note 可以加解释而不丢失含义；
同时 `NotePrefixesAreStillWhatCommanderWritesTests` 直接读 `commander.py` 源码断言两个前缀还在——
`commander` 改了措辞而这里没跟上，判定会静默退回「没发」，正是刚修掉的那个缺陷。

## 真实数据顺带验证了四道守卫

同一批历史订单里，`2026-10-30T0345442451860000-7cf3d44f`（`qoder_cn`）判定 `acked`，
但候选有 2 个、其中 1 个被拒 `not_assistant`：

```
evidence  : role=assistant direction=incoming session=64928  accepted
rejected  : role=unknown   direction=unknown   session=64928  not_assistant
```

也就是说**真实会话里确实存在一条带 token、但角色/方向都不明的行**（我们自己那句请求），
守卫在真实数据上把它挡下来了。这一点在 v0.6.10 只有夹具证据，现在有了实测。

## 回归

| 环境 | 结果 |
|---|---|
| Windows `.tools/agent-runtime` 3.13.9 | **968 passed, 3 skipped, 113 subtests**（第二次全量；第一次见下） |
| WSL anaconda 3.12.7 | **921 passed, 50 skipped** |
| 新增 | `test_ack_protocol.py` +7（`CeasedIsNotOneFactTests` 6、note 前缀守卫 1） |

两边都 +7（v0.6.10 是 961 / 914），正好是上面两组新测试。

**Windows 第一次全量不是干净的，照记**：`1 failed, 967 passed, 3 skipped`，
失败项 `test_improvement_stage_watcher.py::test_second_instance_fails_before_reconciliation`。
定性依据三条，不是「大概是偶发」：

1. traceback 里是 `subprocess.TimeoutExpired`（`timeout=12`），不是断言失败；
2. 该文件单跑 **9 passed / 57.84s**——每次 pwsh 启动约 6 秒，全量并发下超过 12 秒完全可能；
3. 第二次全量 **968 passed / exit 0**，同一台机器、同一份代码。

那条 12 秒是「别挂死」的护栏，真正的断言是 `returncode != 0` 与 stderr 含 `watcher.lock`。
所以这条失败说的不是被测行为，而是**护栏相对成本定得太紧**。本版只记录，不改它——
一个以「状态必须为真」为主题的版本，不该顺手改一个和主题无关的测试。
`v0.6.12` 单独处理（抬高挂死护栏，断言一个字不动）。

## 没做的

`ack_tracker.py` 未合并、`TASK_RESULT_READBACK` 未实现。本版只纠正了一个错判，
没有扩大覆盖范围。
