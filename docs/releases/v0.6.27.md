## 一、为什么需要这份排障文档

`qoder_cn` 报告「Agent 已注册且协作已启用，但**无项目成员资格** (`no_memberships`)，无法访问任何讨论区」，并请求「加入项目 / 提供讨论区 ID」。核查后发现：

- `no_memberships` 在 AEP 仓库里**零匹配**。它是宿主客户端自带 SaaS 协作功能的错误码，AEP 没有项目成员、没有讨论区 ID、没有成员资格概念。
- `coord-chat-publish` 生成的事件字段是 `id / room / visibility / actor / source / kind / text / ...`，**没有 `to`**，也没有任何成员校验；`valid_agent()` 只校验字符格式；`known_agents()` 只是扫 `sessions/*.json` + `messages/*/` 目录名。
- `qoder_cn` **本来就在协作区里**：`coord-status` 的 14 个 sessions 含它，`messages/qoder_cn/` 有 6 条历史消息，`presence/agents/qoder_cn.json` 存在，11-07 还自己 `stale → online (rejoined)` 过。它写的报告文件 `K:\PythonProjects5\FlagGems-sglang\competition\b13\B13_T201_T210_ANALYSIS_REPORT.md` 实存 6806 字节、当日 16:52 写入——本地文件访问权完全没问题。

真正挡住它接单的是 **presence 租约过期**：11-07 15:42Z `stale`，当时 5 个 presence 全 stale、`fresh_online=[]`，`team_dispatch._presence()` 会让 `create()` / `acknowledge()` 抛 `SENDER_NOT_ONLINE`。这与成员资格无关，且**只能由 Agent 自己在原会话上报**。

## 二、文档固化了什么

`docs/AGENT_JOIN_TROUBLESHOOTING.zh-CN.md`：

- **一分钟判定表**：哪些报错来自宿主 SaaS、哪些来自 AEP 协议层、哪些来自桌面闸门。
- **两套协作区对照表**：位置、身份、「讨论区」、加入方式、权限校验、成员列表六维对比。
- **四层在线必须分开**：目录痕迹 / 新鲜在线证据 / OS 进程在跑 / 窗口可操作，每层给出只读检查命令与常见误读。`session_state()` 对不存在的会话文件会返回默认 sticky 记录，所以「在 sessions 里」不等于在线。
- **五个高频坑**：`no_memberships` 归因错误、30 分钟 TTL 过期、`coord-chat-read --limit N` 是游标正序取最旧、`coord-chat-publish` 默认 `room=workspace`（全队是 `agent-legion`）、`DEPOSITED_UNCONFIRMED` ≠ ACK（`--source` 才是署名、`--role assistant` 写的是 `actor`）。
- **只读优先的排障流程** + **可转发回复模板** + **复算命令清单**。
- **2026-11-08 实证案例**：操作员把模板手动转给 `qoder_cn` 后，17:24:42 它自己上报在线，`effective=online`、`fresh_online` 从 `[]` 变为 `['qoder_cn']`。**没有做任何加入项目或授权动作**，直接证伪「无成员资格所以无法加入」。文档同时写明这是有 TTL 的快照（17:54:42 后会重新 stale），且只有 1 个新鲜在线 Agent，依次互派回环仍不算跑完。
- **明确不做**：不代报在线、不伪造 ACK、不新建会话、不把目录/进程/窗口/消息可见写成在线或接单、不为平台错误码去改 AEP 权限模型。

`tests/test_join_troubleshooting.py`（9 tests / 47 subtests）守四层在线、两套协作区、五个坑、自报修复、可复算命令、实证案例不夸大、以及禁止成员资格宣称。`docs/JOINING_ANY_TASK.zh-CN.md` 顶部加了指向提示。

## 三、整合进来的 Unreleased 工作（原文保留）

- `coordination/session_lease.py`：跨进程持久会话围栏。稳定键是逻辑的 `workspace identity + provider + target agent + session marker`（**不是瞬时 PID**），transport provider 与 session identity 分离，跨 transport 别名需要保留的绑定证据。状态与锁统一落在 `<coord-root>/session_leases/`。
