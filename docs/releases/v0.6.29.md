# v0.6.29 — 架构重构：commander 模块拆分与 foundation 基础层收敛

## 核心变更

- **拆分 `commander` 为三层架构** (`commander_base` + `commander_uia` + `commander` 重导出):
  - `commander_base.py` 持有不依赖桌面传输面的常量、持久化状态、订单队列与重试逻辑。
  - `commander_uia.py` 持有桌面传输叶子函数（UIA/OCR/CDP/Profiled）。
  - `commander.py` 保留业务编排逻辑（`tick`, `dispatch`, `perceive`, `ack`），通过显式重导出维持 100% API 兼容。
  - 文件规模从 72KB 缩减至 ~39KB，职责边界清晰。
- **收敛 `foundation` 基础层** (`foundation/io.py` + `foundation/ids.py`):
  - 将分散在各模块的 crash-safe 原子 IO (`_atomic`) 和确定性时间戳 (`_utc`/`iso_now`) 统一收口至 foundation 层。
  - `ui_fallback.py` 移除本地重复定义，替换为 foundation 等效别名，消除重复定义带来的维护风险。
- **测试修复与同步** (`test_unattended_resume.py`):
  - 重构后模块属性路径发生变化，同步更新 `unittest.mock.patch.object` 的靶向模块（如从 `commander.commander_base` 改为 `commander_base`）。
  - 修复 `_auto_resume_due` 和 `AUTO_RESUME_BACKOFF_SECONDS` 的 patch 靶向，从 `commander` 更正为 `commander_base`。
  - 修复 `_profiled_readiness` 的 patch 靶向，从 `commander_uia` 更正为 `commander`（重导出）。
  - 全部 13 个测试用例通过。
