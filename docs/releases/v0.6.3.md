# v0.6.3 — 一条命令和调度器必须看同一份 profile

本次修的是「同一件事存了两份，其中一份过期」这一类缺陷，共三处，都在「手」这条路上。

## 1. `coord-uia` 读的是硬编码表，不是 profile 文件

`cli.UIA_CLIENTS` 里 Qoder 的 `exe` 还停在 `0.4.11`（运行中是 `0.5.1`），也不带
`-AllowUnknownPath`。于是操作者的命令直接失败：

```
LAUNCH_FORBIDDEN: no window for this agent
```

而调度器用 `coordination/ui_profiles/qoder.json` 却能找到同一个窗口。现在改为
**profile 文件优先、内置表只作兜底**，参数映射收成 `ui_fallback.profile_args()` 一份，
两条路共用（OCR 语言、composer hint、发送按钮几何、剪贴板开关都在里面）。

修完实测（普通权限终端，提权 Qoder）：

```
status: transcript-captured    pid: 22796    transcript_chars: 2100
```

## 2. `-AllowClipboardPaste` 从未从 Python 传过

脚本的守卫是 `if (-not $selection -and -not $AllowClipboardPaste) { throw 'NO_INPUT_CONTROL' }`——
「读不到可编辑控件时没有出路」。现在按 profile 的 `allow_clipboard_paste` 显式开启，
默认关闭：粘贴落在激活时获得焦点的位置，脚本自己的报错就写着 *only with human supervision*。

## 3. 路径校验恰好在最需要它的地方静默跳过

适配器用 `Process.MainModule` 比对 `-ExpectedPath`，而它**对提权进程直接抛异常**，
被 `catch` 吞掉后检查就跳过了——提权客户端正是本项目的操作规则。新增
`coordination/process_info.py`，用 `QueryFullProcessImageNameW`
（只需 `PROCESS_QUERY_LIMITED_INFORMATION`，与提权检查用的是同一档权限）：

```
profile_path_check: {"expected": "D:\\Programs\\Qoder\\.qoder-versions\\0.5.1\\Qoder.exe",
                     "actual":   "D:\\Programs\\Qoder\\.qoder-versions\\0.5.1\\Qoder.exe",
                     "match": true}
```

`match: null` 表示「没检查」，`reason` 说明为什么——不是「通过了」。

## 4. deliver 的早退分支也回答 `input_found`

`urgent-interject-unavailable`、`input-not-confirmed`、`send-control-not-found`
三个分支原来只给状态，不说有没有找到输入控件。证据阶梯要机器可判，失败分支必须回答
和成功分支同一个问题。

## 更正上一版文档的结论

`docs/HANDS_AND_FEET_STATUS_20261031.zh-CN.md` 上一版说「`deliver` 没有几何兜底」。
Qoder 的 `transport` 是 `ocr`，`deliver` 本来就会切到 `compose` 模式，
`-AllowComposerGeometryFallback` 与 `-ComposerXRatio/YRatio` 一直在传——通路是通的。
`INPUT_SUBMITTED` 剩下的唯一条件是**执行器以管理员启动**（`drivable: false`,
`blocked_by: TARGET_NEEDS_ELEVATION`）。
