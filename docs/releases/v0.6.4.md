# v0.6.4 — 提权执行器真的把消息发出去了

这一版没有新机制，只有一件事：把「手」这条路的最后一段接通，并让回执不再骗人。

`AEP-UI-PROBE-20261031T203037` 用 `Start-Process -Verb RunAs` 起的执行器，
打进了提权 Qoder（pid 22796）的会话，读回时事件号出现在我们自己那句话之外：

```
ACK AEP-UI-PROBE-20261031T203037
```

即证据阶梯走到 `AGENT_ACK`。达成之前修掉三个各自独立、又互相掩盖的缺陷——
它们的共同点是：**工作已经成功，回执却说失败**。

## 1. 回执在出口处被控制台编码器毁掉

`Write-Report` 把 JSON 交给 PowerShell 输出流，控制台编码器因此进了链路；
提权进程的 OEM 代码页表示不了中文。同一份数据两条路的对照：

```
-OutFile 落盘：52,750 个非 ASCII 字节，仅 7 个 '?'   <- 完美 UTF-8
stdout 回执  ：中文全部变成 '?'                       <- 只有回显被毁
```

这种证据比没有证据更坏，因为它把人指向错误的方向。现在直接向标准输出写字节：

```powershell
$bytes = [System.Text.UTF8Encoding]::new($false).GetBytes($json + "`n")
$stream = [Console]::OpenStandardOutput()
$stream.Write($bytes, 0, $bytes.Length)
```

## 2. `coord-uia` 在提权下崩溃

提权后 `locale.getpreferredencoding()` 是 **cp1252**（非提权时 UTF-8），
而适配器写 UTF-8 中文。`subprocess.run(text=True)` 的读线程死在第一个中文字符上，
`stdout` 变成 `None`：

```
AttributeError: 'NoneType' object has no attribute 'splitlines'
```

改走 `uia_argv.run()`，与驱动器同一个执行器。另三处
（`transcript_patrol`、`octo_transport`、`wake_daemon`）是同一模式的同一类缺陷，
一并加显式 `encoding="utf-8"`——缺陷在模式里，不在某条命令上。

## 3. 发送只校验一次，而且校验得太早

会话正文本来就包含输入框，读回循环可能第一次轮询就命中，而应用还没处理发送；
composer 检查只跑一次、看到事件号还在框里，就报 `submitted-unconfirmed`。
消息其实已经送达。**这里的假阴性比假阳性更坏：它会诱发重复发送。**

现在轮询到清空；若仍不清空，通过获得焦点的控件粘贴再发一次。重试不是"等慢一点"的补丁：
`ValuePattern.SetValue` 更新视觉编辑框但**不触发** web 应用的 input 事件，
发送按钮因此保持禁用、Enter 也无反应。回执新增 `composer_clear_polls` 与 `send_retry`。
