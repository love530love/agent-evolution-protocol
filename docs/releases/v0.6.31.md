# v0.6.31 — 更新器安全身份与桌面执行证据加固

## 本版解决的边界

这一版收紧的是 Windows 桌面 Agent 的“我找到了谁”和“我到底看见了什么”两类事实。
它让可被批准的客户端更新路径、会话指纹、窗口锚点、后台巡检和受限提权执行器使用同一份
可审计规则；它不把这些底座能力误写成任何目标 Agent 已接单。

完整生产验收仍然是：

```text
定位原会话 → INPUT_SUBMITTED → MESSAGE_VISIBLE → AGENT_ACK → TASK_RESULT_READBACK
```

本版不新增一个真实外发的五段闭环。

## 主要变更

### 1. 更新器路径成为显式身份策略

桌面客户端更新后，实际进程常从版本化目录运行。v0.6.31 新增
`allowed_exe_roots`：它只接受同一 exe 文件名位于 profile 显式声明的绝对根目录下的路径，且按
Windows 路径边界比较。

- Qoder 与 Qoder CN 有独立的内置 updater 根；同名 exe 不会跨客户端互认；
- client registry、Python UIA 进程枚举和 PowerShell UIA adapter 走相同的匹配规则；
- 注册/加载阶段拒绝相对根、空根和重复根；
- 导出的示例 profile 仅保留可替换占位符，不再泄露本机绝对路径。

这解决的是“可信版本更新导致已核验会话被误判失配”，不是“任意同名程序可以冒充目标”。

### 2. 指纹和锚点有了可解释的生命周期

对于已获准的 updater 版本路径，session fingerprint 使用 profile 的逻辑 `exe` 以跨版本稳定；
同时把实际路径保存在 `actual_exe`，把判断理由保存在 `exe_match_mode`。越出批准根的路径仍改变
指纹并触发拒绝。

窗口锚点则区分：

| 状态 | 含义 |
|---|---|
| `CURRENT` | 当前 PID 与标题都匹配被记录的锚点 |
| `STALE` | 被记录 PID 已不再对应候选窗口 |
| `PID_TITLE_MISMATCH` | PID 存在但当前标题不再匹配 |
| `UNCONFIGURED` | 尚未记录锚点 |

`fingerprint_match` 现在不会再由“窗口标题与指纹字符串不同”这种无意义比较伪造结论；若 discovery
没有实际观测完整 fingerprint，会明确报告 `NOT_OBSERVED_IN_DISCOVERY`。

## 3. 后台巡检不再为 OCR 抢占桌面

`transcript_patrol` 改用 UIA `observe`：目标未在前台时，巡检不会为了截图而激活、聚焦或输入。
它返回 `uia-background-unreadable` / `BACKGROUND_CAPTURE_UNVERIFIED`，把“不知道”留作不确定，
等待可信的前台或专用证据源。

这是对“后台监控不得抢占用户当前工作”的改进；普通需要写入的 delivery path 仍必须单独通过
原会话、session lease 和 preflight 检查。

## 4. 单订单提权执行器与 session-attestation 基础件

新增两个刻意窄化的构件：

1. `scripts/run-elevated-desktop-order.ps1` 只允许一个精确的、已经 `DEPOSITED`、
   `allow_launch: false` 的 order。默认 preview，真实调用必须 `-Apply`、交互式高完整性 token、
   exact `OrderId`/`EventId`/`ReceiptPath`。它不扫描队列、不新开客户端/会话，也不把 executor
   启动当成消息送达。
2. `coordination/session_attestation.py` 把 profile digest、session fingerprint、观测 surface 和
   短时 lease 固化成可重启读取的前置证明。它的 `delivery_proven` 固定为 false。

严格 attestation 尚没有接入生产发送闸门：当前整窗 OCR/侧栏 marker 不足以证明输入框属于活跃
原会话。后续必须先加入 active-header/transcript 的专门证据 adapter，才允许把“严格证明”变成
输入前硬门。

## 本机验证与可复核事实

- 本机全量回归（包含本版全部新增测试）：**1669 passed, 2 skipped**，169.91 秒，exit 0。
- `python -m agent_evolution_protocol --version` 以及 `pyproject.toml`、`__version__`、版本一致性测试
  共同锁定为 **0.6.31**。
- 发布前只读 discovery / fingerprint 核对（2026-11-11 06:12 UTC）观察到：Qoder 运行在受允许的
  `.qoder-versions` 路径，使用 `exe-trusted-root` 身份模式，窗口 anchor 为 `CURRENT`，且其已保存的
  会话 fingerprint 与当前观察值一致。Qoder CN 有独立受允许根；当前运行路径同样受根策略约束，但其
  旧 anchor 被诚实标为 `STALE`、没有已保存 fingerprint，因此系统保留未知而非自动锚定。

上述第三项是本机状态观测，不是对外发消息、目标读取或 ACK 的证明。

## 未通过的生产门槛

- 没有本版发起的 Qoder、Qoder CN、WorkBuddy、WorkBuddy AI 或 CodeBuddy 原会话真实
  `MESSAGE_VISIBLE → AGENT_ACK → TASK_RESULT_READBACK` 记录；
- elevated worker 尚未在一个有意义的真实 `DEPOSITED` order 上执行 `-Apply`，因此只具备代码与
  回归覆盖，不具备实机 delivery 证明；
- session attestation 尚未成为写入前生产 gate；
- Browser Bridge 仍未作为受控 desktop delivery adapter 与这些证据链实机接线。

这些状态保持为 HOLD，而不是因为版本发布而被默认关闭。

## 升级与回滚

先读取当前身份，确认没有跨客户端认领，再做任何写入：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
python -m agent_evolution_protocol coord-client discover --agent qoder
python -m agent_evolution_protocol coord-client fingerprint --agent qoder --show
```

配置 versioned updater 根时，只填该客户端的绝对目录；不要为“省事”把宽泛的磁盘根加入
`allowed_exe_roots`。如需回滚，使用此前发布的 annotated tag；不要在协作工作区做破坏性 reset。
