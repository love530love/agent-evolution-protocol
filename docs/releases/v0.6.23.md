digest 同步；同步修正
`docs/coordination/THIRD_PARTY_CAPABILITY_ABSORPTION_20261102.zh-CN.md`
里两处写死的计数。守线恢复 `56 passed, 174 subtests`。

## 2. 纠正通报里的「CRLF 阻塞」结论

hal 的报告把全树 CRLF 判为 CRITICAL，要求执行 `git add --renormalize .`。
在 Windows 宿主机上实测：

```text
git diff --check                 → CLEAN
git config core.autocrlf         → true
git ls-files --eol               → i/lf  w/crlf（索引是 LF）
git diff --stat                  → 仅 cli.py 28 行真实改动
```

工作区 `w/crlf` 只是 `core.autocrlf=true` 的正常表现，**索引里没有污染**。
照它建议做 renormalize 反而会制造巨量无意义 diff，因此**没有执行**。
hal 新增的 `.gitattributes`（文本 LF、`.ps1` CRLF、二进制声明）合理，予以保留并一起提交。

另外 `.git/index.lock` 是个 0 字节残留（16:51 创建），而本机所有 `git.exe`
进程都启动于 10-31 或 11-04，时间对不上；`git add` 实测报
"Another git process seems to be running"。确认后删除该残留锁，写操作恢复。
（删除前核对了大小、创建时间与进程启动时间，没有按名字猜归属。）

## 4. 把「协作区通报」固化成能力

上一轮手工通报暴露三个真实坑，本版新增 `coordination/legion_announce.py`：

1. **`coord-chat-publish` 默认 room 是 `workspace`**。全队共享时间线用的是
   `agent-legion`（既有 45+ 条事件同 room）；hal 的审计通报就发进了 `workspace`，
   只有遍历 events 目录才看得到。⇒ 新能力把 room 写死为 `agent-legion`，
   并直接用 `conversation_journal.append_event(actor=source, kind="message")`，
   不再被 CLI 把 `--role` 映射成 `actor`。
2. **`coord-chat-read --limit N` 是按游标正序翻页**（`read_events` 排序后取
   `after` 之后最早 N 条），不是取最新。刚发的通报看起来像没发出去。
   ⇒ 正确验证方式写进每次回执的 `read_guidance`。
3. **`command_memory.announce()` 正文与 `bridge.AGENTS` 名单硬编码**（7 个、
   不含新 Agent），`bridge.agent()` 白名单还会拒新名字。⇒ 写进 `announce_trap`。

设计边界：

```text
plan()  →  [仅 --apply] append_event(room="agent-legion")  →  DEPOSITED
```

- 默认只读预览，零写入；`--apply` 最多追加 **1 条**共享事件；
- 收件名单从 `coordination/messages/*/` **动态推导**（实测 14 个，含 claude），
  并给出 `coord-send --mailbox-only` 命令清单；
- **不自己写信箱**：`coord-send` 的消息格式是既有标准，复制即第二套标准；
- 回执只认 `DEPOSITED`，`delivered=false`、`acknowledged=false` 恒假，
  不宣称送达/已读/ACK；**只有 `VERIFIED` 能关单**；
- 硬字段 `models_loaded=0` / `processes_started=0` / `ui_touched=false` /
  `deployment_performed=false` / `system_tasks_registered=false`；
- **不新增 `coord-*` 命令面、不新增 schema、不碰桌面**（用模块入口 +
  `scripts/announce-to-legion.ps1`），避免再次命令面漂移。

配套：`tests/test_legion_announce.py`、`skills/aep-legion-announce/SKILL.md`、
`docs/LEGION_ANNOUNCE.zh-CN.md`、`skills/README.md` 与能力卡守线。
