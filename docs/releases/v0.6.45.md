# v0.6.45 — 接手态势板：额度受限下的只读指挥权接力视图

## 本轮交付

- **新增接手态势板**（`coordination/succession_board.py`）：只读聚合
  `capability_roster` / `legion_ledger` / `collab_health` / `command_handoff` /
  `relay` / `presence` / claim 七类既有事实，回答弱 agent 的核心问题：
  「现在谁在指挥、哪个角色空着、我能不能接、缺什么证据」。
  CLI：`python -m agent_evolution_protocol.coordination.succession_board
  --coord-root coordination [--at <ISO8601>] [--format brief|json]`。
- **边界严守**：零写入、零子进程、零网络、零模型导入；所有判定复用既有模块，
  来源不可读则 `verdict=DEGRADED` + `SOURCE_UNAVAILABLE:*`，不猜状态。
  建议恒 `advisory_only=true / may_advance=false / execution_started=false /
  requires_human_review=true`；`dry_run_command` 只是投递预览，不认领角色、不算 ACK。
- **不新增标准**：`schemas/` 仍为 7 个；不改 `cli.py`，不注册新 `coord-*` 命令，
  `skill-manifest` 不动，避免与并行 agent 的写入范围撞车。
- **能力卡与文档**：`skills/aep-succession-board/SKILL.md`（cli / model_required=false）、
  `skills/README.md` 条目、`docs/SUCCESSION_SITUATION_BOARD.zh-CN.md`（设计 +
  2026-11-22 真实读数 + 让缺口闭合的最小动作）。
- **测试**：`tests/test_succession_board.py` 14 项（三闸门、stale/额度/能力失败路径、
  零写入、固定时刻确定性、CLI 双格式、来源损坏降级）。守线复算
  `test_succession_board + test_capability_cards + test_skill_manifest`
  = 60 passed / 212 subtests。

四个角色全部 `UNCOVERED / STANDBY / holder=None`；`takeover_advice=0`；
28 个命名缺口，关键为 `NO_CAPABILITY_DECLARATION`、`ACK_PENDING:1`、
`ROLE_NOT_HELD:*`、`QUOTA_UNDECLARED:*`、`NO_FRESH_PRESENCE:*`。

capability/quota 与 holder 显式 handoff，不是第三个状态机。claim ≠ 角色 holder。
