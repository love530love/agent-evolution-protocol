# v0.6.32 — 受限提权执行器的 CI 纠错版本

## 为什么需要一个新版本

v0.6.31 已经发布且保留其历史 tag。随后 GitHub Actions 在 Windows Python 3.10 与 3.12 的干净
runner 上一致发现一个真实问题：当调用者显式传入外来的 Python 可执行文件时，提权任务注册器先
检查“仓库是否已有已安装 runtime”。在没有任何可选 runtime 的 CI checkout 中，它因此报告
`APPROVED_AEP_PYTHON_NOT_FOUND`，掩盖了本应优先给出的 containment 拒绝
`PYTHON_NOT_APPROVED`。

此版本只修复这个错误判别顺序。它不重写 v0.6.31，不把已发布 tag 移到新提交，也不借此声称任何
桌面 Agent 已被唤醒或接受任务。

## 修复内容

`scripts/register-elevated-desktop-order-task.ps1` 现在有两个明确分支：

1. 若调用者显式指定 `-Python`，先解析该文件并与 repository-local allow-list（
   `.tools\agent-runtime`、`.tools\desktop-sdk`、`.venv`）比较；不属于 allow-list 的文件立即以
   `PYTHON_NOT_APPROVED` 拒绝。
2. 若调用者未指定 `-Python`，才从上述 allow-list 中挑选已经安装的 runtime；全部缺失时才报告
   `APPROVED_AEP_PYTHON_NOT_FOUND`。

这样“外来执行器”与“安装尚未完成”是两个可审计、不可混淆的状态。两条分支均不会创建 Scheduled
Task、启动客户端或写入订单回执后才失败。

## 本机可复核验证

在 Windows 本机、以与 GitHub Actions 同一 unittest 发现入口执行：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
& 'C:\Users\love\.codex\runtimes\python311\Scripts\python.exe' -m unittest discover -s tests -q
```

结果：**1305 tests, 4 skipped, exit 0**。其中
`ElevatedDesktopWorkerBehaviorTests.test_registration_refuses_an_unapproved_python_before_task_creation`
在无预装 approved runtime 的临时工作区中验证外来 `cmd.exe` 会收到 `PYTHON_NOT_APPROVED`。

这仍是本机回归证据。新 tag 推送后，Ubuntu/Windows、Python 3.10/3.12 的 GitHub Actions 矩阵必须
独立成功，才可称 CI 通过。

## 保持不变的生产边界

本版本没有新增真实外发的：

```text
定位原会话 → INPUT_SUBMITTED → MESSAGE_VISIBLE → AGENT_ACK → TASK_RESULT_READBACK
```

提权 worker 的执行回执依然只证明它处理了一个受限、精确订单；它不等价于消息可见、目标 ACK 或
业务结果。原会话 attestation 仍未接入生产写入闸门，Browser Bridge 也仍不是已完成实机验收的
desktop delivery adapter。
