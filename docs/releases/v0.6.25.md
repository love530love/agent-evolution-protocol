# v0.6.25 — 桌面投递：暴露 compose，补 UIA 转写并列第二判定源

这一版来自 2026-11-06 的一次**真机强制桌面投递**。它不是新功能预研，而是把那次投递暴露出来的两个真实断口修掉，同时严守一条底线：**不为了让回执好看就放宽既有验收契约**。

## 真机发生了什么

执行器是 `Medium Mandatory Level`。用 `Get-Process.Path` 可读性判定目标完整性级别后发现，Qoder / Qoder CN 主窗口确实提权（UIA 树读到 0 个控件，UIPI 成立），但 ChatGPT / CodeBuddy CN / WorkBuddy / WorkBuddyAI 都是普通 IL，Medium 执行器够得着——上一版「必须 UAC 提权」的结论过粗。

对 ChatGPT 的第一次 `coord-uia deliver` 失败得很干净：`write_method=uia-valuepattern`、复读仍是 placeholder、`status=input-not-confirmed`、没按 Enter、没有假回执。`ValuePattern.SetValue` 不触发 Electron 的 input event，适配器写完立刻复读就 `return`，后面的粘贴补偿根本到不了。真正打通的是适配器里**已经存在**的 `-Mode compose`（剪贴板真实粘贴 + OCR 回读），但 CLI 从未暴露它。

第二次走 compose 后，消息确实进了会话：只读 UIA 转写从 17341 → 20163 字符，含完整事件 ID 与四个探针，对方回复「我会按事件 ID 做一次只读审计…」并开始跑 `rg`。**可适配器回执却写 `task_delivered=false`**，`postflight` 复算三项 failed。根因是 OCR band 按窗口相对比例切分，而该窗口在多显示器上的矩形是 `[960, 429, 2880, 1659]`，比例失真 ⇒ 假阴性。

加上 v0.6.24 见过的「`true` 却四项检查全缺」，结论是：**这个布尔两个方向都不可靠**。

## 本版改了什么

**1. 把 compose 从 CLI 暴露出来**（不是新手脚）

`aep coord-uia compose` 现在与 `deliver` 并列。`WRITING_UIA_ACTIONS` 让两个写动作共用同一组硬校验：必须有 `--event-id`、正文必须包含该事件 ID。适配器本身一行没改。

**2. 新增独立的 UIA 转写第二判定源**

`coordination/uia_transcript_verdict.py` 从只读 `coord-uia capture` 的转写里，以「最后一行含 profile 精确 `composer_hint`」为边界，要求：事件 ID 在边界之上的会话区、不在边界之下的 composer 区、可选探针也在会话区。缺 hint 报 `NO_COMPOSER_BOUNDARY` / `verified=None`，**绝不靠猜行数**。OCR-only 客户端没有 UIA 树，这个源就是 unavailable，不猜。

**3. 并列，不是替换**

`delivery_preflight.postflight()` 新增 `--transcript-file` / `--event-id` / `--probe` / `--composer-hint`，输出 `transcript_verdict`、`sources_in_conflict`、`conflict_note`。三条硬边界：

- 主判 `verified` 仍只由 `action_verification.verdict()` + 四项 `REQUIRED_SEND_CHECKS` 决定，第二源不参与、不覆盖、豁免不了它；
- `advisory_only` 恒 true，`commander._dispatch` 一个字没改；
- 两源不一致时 `sources_in_conflict=true` / `OCR_BAND_FALSE_NEGATIVE_SUSPECTED` 只报事实，不裁决「其实送达了」。UIA 转写只证明**消息可见**，不是 ACK、不是回复、更不是 `VERIFIED` 关单。

刻意**没有**去修 PowerShell 的 `$delivered` 公式：OCR band 仍是独立有价值的信号，动它需要多显示器真机标定，而且会让「改判定来让自己通过」重新成为可接受的先例。

**4. 交付面**

`docs/coordination/skill-manifest.json` 与 `SKILL.md` 已重新生成（`in_sync=true`，命令数仍 91 / documented 27）；更新能力卡 `aep-delivery-preflight`、`skills/README.md`、`docs/DESKTOP_DELIVERY_PREFLIGHT.zh-CN.md` 新增第 7 节，并把新词纳入能力卡守线测试。

另外修了 gitignored 运行时数据：`coordination/ui_profiles/chatgpt.json` 的 Store 包路径从 `26.1029.7803.0` 更新为实测的 `26.1103.3517.0`，现在 `coord-uia observe --agent chatgpt` 不带 `--exe` 即可工作。
