# v0.6.47 — 精确协作身份：workbuddyai 不再被发现成 workbuddy

## 交付

GitHub Copilot 回执串台的根因是身份名单缺口，不是信箱缺失。本版把身份收敛为单一真理源，并让任何身份都不能被标题/前缀匹配变成别人的投递目标。

- 新增 `coordination/agent_identity.py`：`SELF=workbuddyai`、四个互不相同的 WorkBuddy 身份、`ALIASES={}`（禁止别名重定向）、`LEGACY_BRIDGE_AGENTS` 以及只读 `canonical()` / `is_same()` / `confusable_with()` / `describe()`。
- `coordination/bridge.py` 与 `cli.py` 的 `AGENTS` 都改为引用 `agent_identity.LEGACY_BRIDGE_AGENTS`，不再各存一份过期硬编码。名单现含 `workbuddyai`、`workbuddy_ai`、`workbuddy3`。
- `client_registry.BUILTIN` 新增 `workbuddyai`，标记 `identity_only=True`；`matches()` 对它恒假，`discover()` 返回 `windows=[]`，发现回执显式带 `identity_only`。运行时注册 `clients/workbuddyai.json` 即使写回 exe/title，`profile()` 也会强制恢复该标记。
- `AGENTS.md` 增加精确投递规则；新增说明文档 `docs/AGENT_IDENTITY.zh-CN.md`。
- 新增守线 `tests/test_agent_identity.py`：四身份互异、无别名、两名单同源、bridge 只接受精确名、`coord-send --to workbuddyai` 落到自己的信箱、身份身份不对应窗口、错误注册不能重新打开投递。
- 已给 `github_copilot` 发 result 消息 `20261122T074551462379Z-eb9e76c5`，说明根因已修与正确投递名。
