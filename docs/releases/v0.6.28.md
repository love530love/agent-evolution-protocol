# v0.6.28 — 离线验收夹具：把真机判定失败冻结成可复算证据

这一版来自对 `github.com/lobehub/lobehub` 的调研，但**落地的是一个纯 Python、零服务、
零登录的本地能力**：把过去几次真机投递里判定器遇到过的假阴性/假阳性，固化成 CI 上
也能重跑的验收夹具。用户明确不要「LobeHub 登录后云端能力」，这条约束贯穿全版。

## 为什么要做

到第 7 节为止，`delivery_preflight` 已经能识别 OCR band 假阴性，但那些结论只存在于
聊天记录和 gitignored 回执里：CI 跑不到、改判定器后没有回归闸门、也没人能保证下次不会
为了让汇总好看而悄悄放宽契约。

上游验收实践里有两条正好对症的思路（**只引方法论，独立实现，不复制源码**）：

1. 声明了 `requiredEvidence` 的检查**不能只凭文字通过**；缺产物就记 `uncertain`
   并**持住**交付。回执里的 `task_delivered=true`、`status=message-visible` 是文字，
   不是证据。
2. 一个有界实验要有六段命名契约 `experiment / effect / safety / oracle / receipt / result`，
   让复核者能分开看「注入了什么故障」「事先期望什么」「实际测到什么」「哪些事绝不能发生」。

## 实现：`coordination/delivery_acceptance_fixture.py`

四份**合成但取自真机**的夹具内嵌在模块里，不读 `coordination/` 运行时文件（否则 CI 必红）。
所有结论都来自既有 `action_verification.from_send_report/verdict`、
`delivery_preflight.postflight`、`uia_transcript_verdict.evaluate`，**不新建第二套判定**。

| 夹具 | 真机来源 | 注入的故障 | 期望 |
|---|---|---|---|
| `ocr_band_false_negative` | 11-06 ChatGPT compose #1 | 多显示器 `rect [960,429,2880,1659]` 让 OCR band 切错 | 主判 `false`、第二源 `true`、冲突具名 → `pass` |
| `boolean_false_positive` | 11-05 qoder interject | `task_delivered=true` 但四项检查字段全缺、无 UIA 转写 | 主判 `null`、**缺证据持住** → `uncertain` |
| `primary_kept_under_conflict` | 11-06 ChatGPT compose #2 | `placeholder_gone=false`，UIA 转写证明送达 | 主判仍 `false`、第二源 `true` → `pass` |
| `submitted_unconfirmed` | 11-06 workbuddy3 | `composer_cleared=true` 但 OCR 回读丢事件 ID 与 hint | 第二源 `null` / `NO_COMPOSER_BOUNDARY` → `pass` |

`requiredEvidence` 可从 `receipt / check_fields / uia_transcript /
event_id_in_transcript / composer_hint / probe` 六类事实声明；任一缺失即
`result.outcome=uncertain`、`matched=false`，**绝不触发写入或重放**。
`fixture_sha256` 从内容稳定重算防漂移；`oracle` 在复算前声明，
`ORACLE_MISMATCH` 判 `fail` 而不是 `uncertain`。

**基线：`3 passed + 1 held + 0 failed`**。`held=1` 是正确结果，不是测试挂了——
那个 qoder 回执的布尔是假的，缺证据就必须持住。

```text
python -m agent_evolution_protocol.coordination.delivery_acceptance_fixture
# {"cases":4,"passed":3,"held":1,"failed":0,"uncertain":1,...}
```

## 与上游的边界（用户约束）

**不引入 LobeHub 登录后云端能力**：
- 既有 `docs/EXTERNAL_TOOLS.zh-CN.md` 已定「不连接官方服务、不发起登录」；
  `external_tools.py` 对服务器通知直接抛
  `LobeHub server integration disabled: local-only project policy`。本夹具不碰这些路径。
- 明确排除：`lh login` / `lh notify` / Marketplace CLI / `apps/auth` Workers /
  agent-gateway / device-gateway / cloud-sandbox / creds / Remote Server Sync，
  以及自托管运行时本身（PostgreSQL + Redis + S3/RustFS + SearXNG + 常驻 Next.js）。
- 上游 `LICENSE` 是 **LobeHub Community License**（Apache-2.0 + 衍生分发需商业授权），
  `package.json` 却写 `MIT`、GitHub API 返回 `NOASSERTION` ⇒ 复制源码更不可接受。
  本模块只独立实现两条方法论；例外是 `.agents/skills/acceptance/LICENSE` 单独为
  Apache-2.0，但本版也**没有**复制它的任何文本。
- `safety` 恒为 `no_adapter / no_network / no_process / no_write / no_login /
  no_model / no_ui_input = true`；`run_all()` 的硬字段全为 `0/false`。
  AST 守线禁 `socket / urllib / requests / httpx / subprocess / threading /
  asyncio` 与模型模块；文本守线禁 `lh login` / `lobehub.com` / `market-cli` /
  `oauth` / `api_key` / `access_token`。
