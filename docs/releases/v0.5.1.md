# v0.5.1 — OCR 不是缺语言包，是没接线

发布日期：2026-10-31
上一版：`v0.5.0`（Persistent Federation Workspace）

## 一句话

中文界面读不出来，不是机器缺识别器，是 `-OcrLanguage` 只接到了 10 个调用点里的 1 个；
再加上 Windows OCR 在汉字之间插空格，任何中文 marker 都不可能匹配。
两个都修了，`observe` 现在能读回 3046 个中文字并判出 `ready`。

## 修了什么

| 问题 | 症状 | 修法 |
|---|---|---|
| `jsonschema` 未声明 | CI 四个 Python job 全红，`unittest discover` 直接 `ModuleNotFoundError` | 新增 `test` extra，CI 装 `.[test]`；缺依赖时明确 skip，不再炸掉发现流程 |
| 测试自身不可移植 | Windows 3.10 上 `AssertionError: 1 != 0` | 子进程 stdout 是平台 locale（cp1252），不再让它打印中文，改为 ASCII 转义后再断言 |
| OCR 语言只接了 1/10 | 中文界面被 en-US 读成拉丁近似物，`input_found` 恒 false | `Get-WindowOcrText` 默认继承 `$script:OcrLanguage`，一个点覆盖全部调用 |
| 汉字之间被插空格 | `Contains("插话")` 永远为假 | 在 OCR 出口合并两个中文字之间的空白，保留英文词距与中英交界 |
| `observe` 读不到 Electron 文本 | `transcript_chars: 0` 被误读成"窗口里没字" | UIA 为空且请求了 OCR 时回退，并写 `transcript_source: ocr` |

## 证据

修复前后的同一命令（Qoder 22796，最大化可见）：

```
修复前: ocr_language='en-US'  transcript_chars=0     state=unknown  input_found=False
修复后: ocr_language='zh-Hans-CN'  transcript_chars=3046  state=ready
        ready_hits=["发送","Send","Submit"]
        interject_hits=["插话","继续执行并发送","继续执行"]
```

全量回归：**733 passed**（本机 `D:\A\python.exe` 3.13.9）。
`python -m unittest discover -s tests` 单独跑一遍（4m09s，退出 0），确认 CI 第一步不再挂。

## 仍然没做到的

`INPUT_SUBMITTED` 及之后仍未达成，原因已换成一个更明确的缺口：
Qoder 是 Electron 且未开无障碍，UIA 里没有可编辑控件，而 `deliver` 模式没有几何兜底
（`-AllowComposerGeometryFallback` 只接在 `compose` 上，`-AllowClipboardPaste` 从未从 Python 传过）。
profile 里的 `composer_x_ratio` / `composer_y_ratio` 配好了但没人读。

这条路径会真的往会话里打字，第一次必须在有人在场时跑。
