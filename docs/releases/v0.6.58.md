# v0.6.58 — 原会话五段验收器与只读结果回收

发布日期：2026-11-28

本版把原先分散在 profiled relay、Commander 回执与会话总线中的事实收束为一个
明确的单目标验收入口：

```text
SESSION_LOCATED → INPUT_SUBMITTED → MESSAGE_VISIBLE → AGENT_ACK → TASK_RESULT_READBACK
```

## 交付

- 新增 `aep coord-desktop-acceptance`。默认是 `PREVIEW`，只校验严格 profile
  与请求哈希；不启动客户端、不输入、不点击、不发送、也不写 receipt。
- 显式 `--apply` 才会调用现有 profiled UI relay 一次。它不会另造传输通道，继续
  复用共享 session lease、桌面输入锁、严格原会话 attestation、可见消息读回和
  challenge ACK。
- 验收 manifest 绑定 relay 的 `agent` 与 `event_id`，并且从已落盘的 relay
  receipt 重读证据；内存返回、错目标/错事件或缺失/不可读 receipt 都只能得到
  `HOLD`，不能产生 `COMPLETE`。
- 五段严格单调：严格会话 attestation 缺失、发送不确定或消息不可见时，后续
  `INPUT_SUBMITTED`、`MESSAGE_VISIBLE`、`AGENT_ACK`、`TASK_RESULT_READBACK` 不会被
  提升为已验证。
- 新增 `--readback-only`：在 ACK 后结果稍晚出现时，只读取 session-bound 的
  `transcript_bus` 事件并更新 manifest（`READBACK_RECONCILE`），不构造桌面 driver，
  不进行第二次输入或发送。来自本方输出、未知会话或其他会话的标记不能闭环。
- 自动生成 Agent 可读的 `docs/coordination/SKILL.md` 与
  `skill-manifest.json`，并同步能力吸收文档的命令统计为 106 个子命令。

## 验收

```text
2255 passed, 7 skipped, 1060 subtests passed in 146.01s
```

另做了本机 `qoder_cn` profile 的 `PREVIEW`：命令返回 `PREVIEW` / `EXIT=0`，并且
没有触发任何桌面输入、点击、发送或 receipt 写入。该预演只证明配置能被安全解析，
**不证明** Qoder CN 收到消息、回复 ACK 或完成任务。

## 已知边界

- 真实 `COMPLETE` 仍需要对某一个明确授权的原会话执行 `--apply`，并获取同事件的
  target ACK 与 session-bound 结果标记；本发布没有把单元测试或预演称作实机成功。
- `HOLD`、`AWAITING_ACK`、`AWAITING_TASK_RESULT` 和 `UNCERTAIN` 都是非成功结论。
  尤其 `UNCERTAIN` 必须先在原会话 reconcile，不能换窗口、换通道或新建会话盲重发。
- 常驻 Desktop Host 若仍处于 observe-only，只能采集/回读，不会自行执行这条
  `--apply` 路径。
