# v0.6.0 — 问系统，而不是猜像素

发布日期：2026-10-31
上一版：`v0.5.1`（OCR 不是缺语言包，是没接线）

## 一句话

一个系统开关把 Electron 客户端从「3 个元素、只能 OCR、盲点」变成
「400 个元素、3 个输入候选、6 万字符直接读」。这条通道本来就在，我们没用。

## 实测

同一窗口、同一时刻，`SPI_SETSCREENREADER` 前后：

| | 元素数 | 输入候选 | `input_found` | 文本来源 | 字符数 |
|---|---|---|---|---|---|
| ChatGPT 前 | 3 | 0 | `false` | OCR | 靠识别 |
| ChatGPT 后 | **400** | **3** | **`true`** | **UIA** | **60978** |

Chromium 通过 `WM_SETTINGCHANGE` 感知这个标志，所以**已经在跑的窗口也会生效，不用重启**。

## 新命令

```powershell
aep coord-a11y status --pid <pid>    # 开关状态 + 能否驱动
aep coord-a11y check  --pid <pid>    # 自动开启（若关着）+ 双方完整性级别
aep coord-a11y enable [--persist]    # 默认只改运行时，重启即恢复
aep coord-a11y disable
```

## 一个系统级硬约束（实测，代码绕不过）

Windows 拒绝交出更高完整性级别进程的令牌，后果是连锁的：
`OpenProcessToken` 失败 → `ShowWindow` 返回 0 → UIA 枚举 0 元素 → 注入按键被 UIPI 丢弃。

本机实测：

```
Qoder    target_elevation: unknown    drivable: false    # 提权进程
ChatGPT  target_elevation: standard   drivable: true
```

所以：**目标提权，执行方也必须提权，或者把目标改成普通权限启动。**
这条写进回执，比让三步之后的输入静默失败要好。
