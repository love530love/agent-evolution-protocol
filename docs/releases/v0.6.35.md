# v0.6.35 — 桌面执行收束、原会话路线校准与可接力控制面

发布日期：2026-11-15

本版把近期桌面派工实战暴露出的三个问题固化为可验证工程：**原会话
路线不可猜测、短命 MCP 探测必须收束、常驻协调循环不能反复自我拉起**。

## 交付

- 每客户端原会话路线校准：记录客户端/进程/工作区/会话标记与输入发送
  路径，模糊时停下，不把“窗口存在”当作可发送。
- UIA/OCR 混合驱动加固：严格会话证明、输入回读、发送后消息可见性与
  目标 ACK 分层，避免将信箱入队或按钮点击误报为任务完成。
- Windows MCP 探测收束：`coord-desktop probe` 以一次性的 `AEPProbe-*`
  Job Object 承载 worker 与其 stdio 子树；超时只终止本次 probe 的已拥有
  进程树，不按进程名碰 Qoder、Qoder CN、WorkBuddy、WorkBuddy AI 或 Codex
  的宿主 MCP。
- AEP MCP 生命周期账本：`coord-mcp-lifecycle status|prune` 仅记录 AEP
  自有实例的 run ID、PID、心跳和退出状态；prune 只清理过期记录文件，
  永不终止进程。
- 常驻协调控制面：Python supervisor 负责独占锁、心跳和 commander tick；
  PowerShell 仅保留计划任务/Windows 操作薄包装。campaign watcher/control
  加入单实例锁、READY 握手及失败自清理。
- 生成式 CLI 技能清单同步为 92 个子命令，防止新增命令未进入 Agent 可读
  接口文档。

## 验收

```text
1744 passed, 3 skipped, 1018 subtests passed in 176.53s
```

另有 Windows 真实只读 probe：超时 receipt 显示
`process_tree_stopped_verified=true`，且 probe 前后 `windows_mcp` 数量不增。
这证明本次 probe 的树被收束，**不**证明目标客户端收到任何派工。

## 已知边界

真实协作闭环仍必须逐客户端取得：

```text
SESSION_LOCATED → INPUT_SUBMITTED → MESSAGE_VISIBLE → AGENT_ACK → TASK_RESULT_READBACK
```

本版不把 MCP 存活、任务入队、桌面窗口出现、按钮点击或 `MESSAGE_VISIBLE`
升格为 `AGENT_ACK`。运行中的 Qoder / Qoder CN stdio MCP 归其宿主所有；
它们不属于 AEP 的清理范围。
