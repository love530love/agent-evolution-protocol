# v0.6.19 — 长任务心跳接合：零模型、零显存、默认只读

本版回答操作员的两个问题：

1. 「LM 已启动，但是不是还要占用本地显存，不是很理想的方案」；
2. 「无人值守的长任务，是不是应该在项目里用小模型或者是用什么程序做一个定时的心跳机制，
   用来轮询或者是向当前指挥的 Agent 发送信息来确保长任务一直持续进行」。

结论是：**显存没被占用，心跳不需要模型，项目里本来就有零模型心跳；真正缺的是把
`missions/M-*.json` 接回既有调度队列的那一段线。** 本版补的是接合器，不是第二套调度器，
也不是常驻服务。

## 1. 显存实测：服务启动 ≠ 加载权重

当日在本机做的只读实测：

| 检查 | 结果 |
|---|---|
| `lms status` | `Server: ON (port: 1234)` |
| `lms ps` | **No models are currently loaded** |
| `nvidia-smi` | RTX 3090，显存 **692 MiB / 24576 MiB**，GPU 利用率 **0%** |
| `GET /v1/models` | 只列出模型清单，未加载权重 |

LM Studio 的 server 开着但没有 `lms load` 时，权重不在显存里。项目里唯一会加载模型的路径是
`insight_miner --propose`，且强制 `--gpu off`（CPU 推理）、`--ttl 60`（60 秒后自动卸载）、
按精确 identifier 执行 `lms unload`；默认的 `insight_miner` 是 socket-free 纯规则路径。

**因此可以直接关掉 LM Studio server，项目默认能力完全不受影响。** 模型缺席是设计好的降级，
不是故障。本版新增的接合器与模型零耦合：代码里没有 `lms`、没有模型 import、没有网络调用、
没有显存占用。

## 2. 心跳不需要小模型

心跳要回答的都是确定性、可复算的问题：租约是否到期、`last_progress_at` 是否超过 900 秒、
phase 是否终态、订单有没有 ACK。规则引擎零误差且能复算；概率模型没有「不知道」输出，
替换不了 fail-closed 安全层。项目此前已立过同样的约束：
`docs/AUTONOMOUS_SUPERVISION_LOOP.zh-CN.md`（不对静默状态进行无意义模型轮询）、
`docs/MAILBOX_PRIORITY_AND_INTELLIGENCE_LOOP.zh-CN.md`（禁止静默模型轮询）、
v0.6.13 / v0.6.15 的「**定时器不是判断**」。

让小模型常驻做心跳，恰好会制造操作员明确反对的三件事：常驻资源占用、静默空转、
以及弱 Agent 因模型能力差异跑不出一致结论。

项目里本来已有的零模型心跳骨架：

| 层 | 既有实现 |
|---|---|
| 判断 · 订单 | `coordination/commander.py:tick()` — 读盘、判 ACK/TTL/自动恢复、派发；不 sleep、不 spawn、不调模型 |
| 判断 · DAG | `federation/engine.py:tick()` — `_stalled()` 用 `last_progress_at` 比 `heartbeat_timeout=900` |
| 循环包装 | `commander.watch()`、`federation/supervisor.py:serve()` — 默认 30 秒、有界 `max_ticks` |
| 事件驱动 | `scripts/campaign-watch.ps1` + `campaign_tick next-due` — 按最近截止时间唤醒 |
| OS 触发 | `scripts/aep-supervisor.ps1`、`scripts/register-supervisor-task.ps1` — 登录时计划任务 + Mutex 单实例 |
| 入队 / 真发 | `commander.submit_order()` → `coord-commander tick` |
| 续租 | `coord-claim-renew`（`assignment.py` 写明每 15 分钟续租，否则判失联） |

## 3. 真正的断口：`mission_id` 没有消费者

`scripts/start-mission.ps1` 只调 `mission_intake.create()` 写出 `missions/M-*.json`
（`state: planned` + 3 个 stage）就退出。调查结果：

- `cli.py` **没有任何 `mission` 子命令**，没有 runner / serve / watch 消费 `mission_id`；
- `mission_supervisor.inspect()` 只返回 `assign / observe / recovery_review /
  report_delivery / blocked_review` 这些**动作建议**，不执行、不循环；
- `mission_runtime.py` / `mission_planner.py` 用 `p.write_text()` 原地覆盖，非原子、无事件日志；
- `mission_graph.py` 是另一套未被消费的 DAG schema；
- `commander.tick()` 与 `engine.tick()` 都**没有持久化调度游标**；
- `docs/NOVICE_LONGRUN_WORKFLOW.zh-CN.md` 早已写明还缺 mission planner、持久化 DAG runner
  和通知策略。

## 4. 接合器：`mission_pulse.py`

一次外部调用 = 一拍，进程随即退出：

```text
scan()  →  gates()  →  verify()  →  [仅 --apply] commander.submit_order()  →  DEPOSITED
```

- `scan()` 只读，动作建议取自 `mission_supervisor.inspect()`，**不复制第二套判定逻辑**。
- 只有 `assign`（阶段 `ready`）允许入队；`observe` / `recovery_review` /
  `blocked_review` / `report_delivery` 一律只报告，交给人处理。
- `gates()` 是 11 类硬拒绝：`ACTION_NOT_ASSIGNABLE`、`NO_TARGET`、
  `INVALID_AGENT_NAME`、`UNKNOWN_AGENT`、`MISSION_PAST_DEADLINE`、`HUMAN_REQUIRED`、
  `WAITING_FOR_EVENT`、`TASK_TERMINAL`、`CLAIM_OWNER_MISMATCH`、`CLAIM_EXPIRED`、
  `ALREADY_QUEUED`。
- **成员名单从文件推导**（`presence/agents/*.json` 与 `clients/*.json` 的实际文件名），
  不用会漂移的硬编码名单；因为 `valid_agent()` 只校验字符、不校验成员。
- `verify()` 从文件重算 mission sha256、`event_id`、全部闸门与正文，任一漂移即拒绝。
  **拒绝的是旧证据，不是永久封禁这个文件**：下一次外部调用会重新 `scan()`，基于新内容
  产生新 `event_id` 重新过闸门；但绝不允许拿已被拒绝的 candidate 去写。
  `queue_candidate()` 是唯一写入口，先复算再入队。
- `event_id` 由 `(mission_id, stage_id, state, updated_at, goal)` 稳定哈希成 `PULSE-...`，
  同一状态重跑不会生成第二单（幂等）。
- 唯一写动作 `commander.submit_order()` 的 docstring 明写
  `Nothing is sent until a tick runs`：不碰桌面、不发消息、不启动进程。
  真正发送仍由既有 `coord-commander tick` 负责，**入队绝不是送达**。

**不新增 schema**（`schemas/` 仍是原来的 7 个）、**不新增 `coord-*` 命令面**
（`docs/coordination/skill-manifest.json` 仍由 `build_parser()` 生成）、不改 mission 文件。

## 5. 触发层归 OS，不归仓库

- `scripts/run-mission-pulse.ps1`：一次性、有界、纯 ASCII；不循环、不 sleep、不后台运行，
  默认不带 `--apply`。
- `scripts/register-mission-pulse-task.ps1`：**默认只打印计划，`-Register` 才会改系统**；
  带 `MultipleInstances=IgnoreNew` 与 5 分钟 `ExecutionTimeLimit`，`IntervalMinutes` 下限 5。
- **本版不注册系统任务**，没有执行过任何 `Register-ScheduledTask`，没有启动常驻进程。
  是否启用、多久一拍完全由操作员决定。

两条硬约束决定了这个归属：其一，本机由 agent 内部 spawn 的常驻进程会随工具调用结束被
**作业对象回收**，`CREATE_BREAKAWAY_FROM_JOB` 不被允许，常驻只能由 agent 之外的东西建立；
其二，操作员明确要求不要让机器卡顿，项目刻意不引入常驻 watcher / 后台线程 / 定时任务。
定时器只负责触发只读命令，**不承担判断**。

## 6. 自动边界与回执

| 动作 | 是否自动 |
|---|---|
| 读 mission、派生成员名单、重算闸门、生成 `event_id` | ✅ |
| 只读 dry-run 预览、报告 `scanned` 与全部拒绝原因 | ✅（默认） |
| `--apply` 时把通过复算的阶段入队为 `DEPOSITED` | ✅（需显式开关） |
| 真正把消息送进客户端 | ❌ 由既有 `coord-commander tick` 负责 |
| 改写 mission 阶段 / 自动接管他人 claim | ❌ |
| 启动模型、常驻进程、后台线程、OS 计划任务 | ❌ |
| 自动评审、晋升、改源码、commit / push / release | ❌ |
| 关单 | ❌ 只有 `VERIFIED` 能关单 |

回执硬字段：`models_loaded=0`、`processes_started=0`、`ui_touched=false`、
`deployment_performed=false`、`system_tasks_registered=false`。任何一个变成真值都算越界。

## 7. 弱 Agent 能力卡

新增 `skills/aep-mission-pulse/SKILL.md`（`min_agent_capability: cli`、
`model_required: false`），按六节规范（何时用 / 前置条件 / 步骤 / 回执判定表 /
失败处置 / 验收门）固化：先只读预览 → 按表判断是否允许 `--apply` → 查回执 →
只有 `VERIFIED` 关单。失败处置明确禁止模型参与心跳判断、禁止常驻 watcher / 后台线程 /
model server、禁止 agent 自己注册系统任务、禁止把 `DEPOSITED` 当送达。
`skills/README.md` 与 `tests/test_capability_cards.py` 同步更新守线。

`docs/LONGRUN_MISSION_PULSE.zh-CN.md` 记录显存实测、既有心跳清单、mission 断口、
接合器流水线、OS 触发归属与「本次未做」；`docs/NOVICE_LONGRUN_WORKFLOW.zh-CN.md`
新增「v0.6.19 补上的接合处（不是无人值守已完成的证据）」，并保留原结论不变：
**不应承诺完全无人值守交付，绝不能把「入队」写成「送达」**。

## 8. 验收

- `tests/test_mission_pulse.py`：空仓扫描量、不可读文件、四种非 assign 动作、11 类闸门拒绝、
  dry-run 零写入、`--apply` 只产生 `DEPOSITED` 且幂等、`workspace_id` 透传、复算防漂移、
  伪造 `event_id` 拒绝、AST 守线（不 import socket / urllib / subprocess / 模型 / 后台线程）、
  脚本纯 ASCII 且默认不注册系统任务、能力卡与边界文档存在。
- 定向回归：`37 passed, 129 subtests`。
- 全量回归：带环境变量连跑两次，结果一致 ——
  `1406 passed, 3 skipped, 601 subtests passed`（163.74s / 171.47s，两次 `PYTEST_EXIT=0`）。
  本机跑全量需要带 `CODEBUDDY_SAFE_DELETE_ENABLED=0`：否则宿主的 safe-delete shim 会拦截
  pytest 临时目录的垃圾回收（`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，count=265），
  会话在写摘要之前被中断（`PYTEST_EXIT=1`、日志无 summary），两次复跑中还有一次
  在 95% 进度行出现偶发的 `F`、另一次没有；加该变量后同一套测试全绿、退出码 0。
  这是本机 shim 与 pytest tmpdir 清理的冲突，不是代码回归。
- 真协作区只读预览：历史 mission 因 `MISSION_PAST_DEADLINE` 被拒绝，**未写任何文件**。
- 临时沙盒 `--apply`：只产生 1 条 `DEPOSITED`；重放返回 `ALREADY_QUEUED`。
- 注册脚本 dry-run：`system_changed: false`。

## 9. 明确没有做的事

- 没有 LM Studio / Ollama 端到端真实推理实测；
- 没有注册任何 OS 计划任务，没有启动任何常驻进程或后台线程；
- 没有实现持久化调度游标、跨重启自恢复演练、统一 artifact 验收器、多日预算与配额调度；
- 没有实现通知策略（「只在需要人处理时通知」仍未落地）；
- **不承诺 7x24 完全无人值守**：OS 计划任务本身还需要登录会话，且 mission planner /
  持久化 DAG runner 缺口仍在。

发版本身按「每次更新务必 push 及发版」的长期约定，由操作员执行提交、推送、打 tag 与
创建 Release；能力本身不触发任何 commit / push / release。
