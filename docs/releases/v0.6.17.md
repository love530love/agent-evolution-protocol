# v0.6.17 — 自动发现与自动审计：默认纯规则，模型随用随走

这一版补的不是另一套监督系统，而是**一个消费者**。项目早就能把失败、弹窗处置和轨迹
append-only 地记下来，但记完之后没有人读：约 16 处事实落在磁盘上，
`coordination/improvement_events/` 与 `coordination/improvements/` 都是 0。
已有的自动监督（`commander.watch`、`federation/supervisor.py`、`campaign_cycle.reconcile`）
回答的是「任务卡没卡」，没有回答「这段时间暴露了什么可以改进的模式」。

同时，操作员提出了两条约束：不希望项目让电脑卡顿、能不用本地模型就更好；
接入的 Agent 能力参差不齐，弱 Agent 也要能完成已经实测通过的能力。
这两条约束塑造了实现形态：**默认纯规则，模型只是可选的措辞建议者且随用随走，
能力固化成查表即用的卡片，而不是依赖 Agent 有多聪明。**

## 1. 断口：事实在落盘，消费端为零

| 事实流 | 现场量 | 改造前是否有人自动读 |
|---|---|---|
| `coordination/battle_events/*` | 7 个 | 部分调度读取 |
| `overlay_audit.jsonl` | 1 行 | 无 |
| `coordination/command_memory/observations/*.json` | 7 条 | 仅在显式 `digest()` 时 |
| `coordination/trajectories/*.json` | 1 份 | 仅在显式 `verify/replay_plan` 时 |
| `coordination/improvement_events/` | **0** | — |
| `coordination/improvements/` | **0** | — |

`improvement.ingest()` 早已提供带证据哈希链的改进日志，只是从来没有被这些事实流自动喂过。
本次没有新建审计 schema、没有新增 `coord-*` 命令、没有改动命令面生成器，
只是把已有的事实接进已有的证据链。

## 2. 链路与自动边界

```
已落盘事实（只读）
  → scan()     4 条确定性规则，逐条输出 count / scanned / triggered / 阈值
  → verify()   重读证据，重算 sha256 + count + scanned + key + rule
  → [可选] advisory   本地小模型只写 title / hypothesis / checks
  → [--apply] 快照 → build_event() → improvement.ingest() → PROPOSED
  → 人工独立 reviewer（claim token / reviewer≠author / 回滚点）
```

四条规则全部是对文件的确定性统计：`unclassified_failure`（未归类失败占比）、
`repeated_failure_signature`（重复错误签名）、`unverified_overlay`（`verified != true` 的弹窗处置）、
`failed_trajectory_step`（轨迹里非零 `exit_code`）。

`scan()` 永远报告 `scanned`（按数据源）与 `measurements`（按规则）。这是硬要求：
「扫描器坏了」「机器很干净」「阈值没到」三种情况必须长得不一样，
否则一次零发现根本不可信。`verify()` 的拒绝原因全部可在回执里查到：
`evidence-changed`、`count-mismatch`、`key-mismatch`、`no-longer-triggered`、
`severity-escalation-rejected`、`finding-marked-as-model-generated` 等。

**自动到此为止。** 不改源码、不评审、不晋升 `ADOPTED`、不 commit / push / 部署；
`deployment_performed` 恒为 `false`，`severity` 恒为 `lead`（一旦被升级就由 `verify()` 拒绝）。
`improvement.py` 自己写着 `security_sandbox: false` 与「test success is not promotion」，
项目当前也没有真正的隔离沙箱，所以「自动改源码」不是 TODO，是被明确排除的能力。

这里的「自动」准确含义是：不需要人事先提出具体问题，也不需要人做判断；
**但触发仍由人或外部调度发起**。本版刻意没有常驻 watcher —— 既因为操作员不希望机器卡顿，
也因为本机由 agent 建立的常驻进程会随工具调用结束被作业对象回收。

## 3. 一个非显然的坑：append-only 日志必须先快照

`overlay_audit.jsonl` 会持续追加。如果直接把 live 文件冻结进改进证据，
之后任何一次 `improvement.advance()` 都会因 `frozen evidence changed` 永久失败。
因此 `_snapshot()` 把证据复制到 `coordination/insights/evidence/<finding_id>/0000-*`，
再对快照做一次 `verify()`。已有快照而源数据变了 → 回执 `evidence-drift-since-snapshot`，
**不静默重定义已有提案**，由人决定是否重新立项。

发布用 `xb` 临时文件 + 同卷硬链接，并发赢家不被覆盖；事件文件重放时内容不变。

## 4. 模型：默认不存在，用时随用随走

- **规则层 socket-free**：`insight_miner.py` 不 import `socket / urllib / requests / httpx / insight_proposer`，
  由 AST 守线（守线会收 `ast.ImportFrom.names` 并断言扫描量，防止空转）。
  模型模块只在 `--propose` 时用 `importlib` 动态加载。
- **模型只做措辞**：`describe()` 只发 `rule / count / scanned / summary`，不发证据路径、哈希或文件内容。
  advisory 严格只接受 `title / hypothesis / checks` 三个字段，拒绝未知字段、绝对路径、命令、控制字符；
  文本只能追加到 `change` 的 `[model_generated advisory; not evidence, not a decision]` 段落，
  **进不了** `event_id`、`kind`、`evidence`、`severity`、`count`。弃答是合法答案。
- **小且随用随走**：`.models/Qwen3-0.6B` 约 1.5GB（已被 `.gitignore` 忽略，权重不进主包），
  LM Studio 默认 `qwen3-0.6b`，Ollama 默认 `qwen3:4b`。会话层用
  `lms load ... --ttl 60 --gpu off -c 2048 -y --identifier aep-insight` 与
  `lms unload aep-insight`：`--ttl` 是崩溃兜底，按精确 identifier 卸载（绝不 `unload --all`，
  不动别人加载的模型），`finally` 中卸载且不掩盖原异常。
  **代码里没有 `lms server start`，没有轮询，没有后台线程。**
- **缺席即降级**：server 关闭、load 失败、HTTP 异常都会让 `model_status` 变成
  `unavailable:<异常名>`，规则结果原样保留。实测当日 `lms status` 为 `Server: OFF`、
  Ollama `11434` 拒连，纯规则路径照常产出候选。

⚠ **诚实边界**：已用测试覆盖 LM Studio `/v1/chat/completions`（`response_format: json_object`）
与 Ollama `/api/chat`（`format: json`、`think: false`）的线格式、加载/卸载与降级分支，
也确认了 `lms load/unload --help` 的参数、模型目录与大小、server 状态。
**但未做 LM Studio 端到端真实推理实测**（`lms ls` 曾挂起并被终止），不声称模型输出质量经过验证。
本能力不需要它。

## 5. 弱 Agent：卡片负责判断，Agent 只抄回执

## 7. 明确没有做的事

- 没有自改代码、没有自动晋升；**这套能力本身不触发 commit / push / tag / release**
  （本次发版是操作员按版本管理约定执行的人工动作）。
- 没有常驻 watcher、没有定时任务、没有自动启动 LM Studio / Ollama 服务。
- 没有 LM Studio 端到端真实推理实测。
- 没有新增 schema、没有新增 `coord-*` 命令、没有修改 `skill-manifest.json`。
- 没有改动 fail-closed 安全层（`routing` / `diagnosis` / `recovery_policy`）；
  概率模型没有「不知道」输出，不能替换这些裁判，本版沿用既有「提议者 + 规则 veto」范式。
- 没有把鲶鱼主动质疑、统一 artifact 验收器、多日预算调度、supervisor 重启自恢复
  等历史待开发项写成已完成。
