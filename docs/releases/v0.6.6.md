# v0.6.6 — 注册表从「一张清单」变成「一道闸门」

这一版没有碰送达路径。它修的是**我们记录候选执行器的方式**：14 个 provider 全是
`candidate`、`probed` 一个都没有，而 `status` 字段谁都能改——那不是状态，是声称。

## 1. `status` 现在必须挣到

新增 `execution_provider_catalog.promote()` / `retire()` / `history()`，三条拒绝：

- **不能跳步**：`candidate → probed → session-accepted → task-tested`，只能走一格。
  中间那一步的探针，是让下一个声明有意义的东西。
- **不能无证**：`probed` 要 `probe_command`/`probe_at`/`probe_result`；
  `session-accepted` 要 `session_event_id`/`session_receipt`/`session_at`；
  `task-tested` 要 `task_id`/`task_receipt`/`task_outcome`。
- **失败不是晋升**：`probe_result` / `task_outcome` 必须是 `pass`。探针没过是一个**结论**，
  不是一个状态——保持 `candidate` 或 `retire`，不许往上走。

每次晋升/退役向目录旁的 `provider_promotions.jsonl` 追加一行（append-only + fsync），
所以「它是怎么到 task-tested 的」永远答得出来。`retire` 从任何活状态都允许，重复退役是幂等空操作
（自动清扫需要这个性质）。

## 2. 目录和 schema 之前是两套标准

`examples/execution-provider-catalog.json` 用了 `integration: vision-service`，
`cua_driver` 还带一个 `license_note`，而 `schemas/execution-provider-catalog-v1.schema.json`
的枚举和 `additionalProperties: false` **两个都不允许**。没有任何测试读过 schema，
所以这份不一致一直发布着——而真正生效的是宽松的那一份。

修法：把 `vision-service` 与 `license_note` 补进 schema（它们描述的是真实存在的集成方式与
真实存在的许可证事实），然后让 `validate_catalog` 也校验 layer / integration 枚举与未声明字段，
再加一条 `jsonschema` 直校验 `test_the_shipped_catalog_matches_its_published_schema`。
**从此改 schema 不改代码会红，反之亦然。**

## 3. 登记 `mage_vl_cowork`，验收条件写在看见数字之前

`layer: desktop_visual`、`integration: vision-service`、`status: candidate`。
`limitations` 里写的是它的真实边界，包括：66.04 的 OSWorld 分数**含自由 bash**，
纯 GUI 阶段只有 45.56；感知无法越过 UIPI；Linux `pyautogui` 训练域与 Windows 不同分布；
`trust_remote_code=True` 会在加载时执行仓库代码。

四条 `acceptance` 都是可测的（`/health`、与 `coord-uia observe` 的**不一致率**、
不给 bash 只给建议区域、一次事件走完 `input_verified` + `composer_cleared` + 同事件 ACK）。
评估与预注册探针见 `docs/MAGE_VL_COWORK_ASSESSMENT_20261031.zh-CN.md`。

## 4. 命令

```bash
aep coord-providers list --layer desktop_visual
aep coord-providers promote --id mage_vl_cowork --to probed \
  --evidence probe_command="curl /health" probe_at="2026-10-31T13:00:00Z" probe_result=pass
aep coord-providers retire --id mage_vl_cowork --reason "probe failed: latency"
aep coord-providers history --id mage_vl_cowork
```

拒绝走 `ProtocolError`（stderr 一行 + 退出码 2），不是 traceback：

```
protocol error: promotion to probed needs evidence: probe_command, probe_at, probe_result
```

## 5. 没做的

- `promote` 只校验证据**存在且非空**，不校验它指向的 receipt 文件真的存在。
  那需要一份「证据格式」约定，等第一个真探针跑完再定，避免先发明格式。
- 目录仍是 `examples/` 下的示例文件；真正的活目录位置还没定。
