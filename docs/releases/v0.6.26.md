# v0.6.26 — ClawChat Protocol v2 官方组织调研：只引协议，不引运行时

本版把 `https://github.com/clawling` 下**全部**仓库的只读调研固化成一份可复算的事实基线。它是纯文档 + 守线测试，**没有接入任何外部服务、没有改运行时代码**。

## 为什么需要这份文档

项目里已经有三处「ClawChat」相关资产，但它们说的不是同一件事：

| 位置 | 实际内容 |
|---|---|
| `coordination/clawchat_transport.py` + `coord-clawchat` | 自研的**本地 TCP + NDJSON** envelope，`execute=True` 才连，默认预览 |
| `docs/CLAWLING_INTEGRATION.md` | 本机 ClawChat GUI 机器通道，`app_version=1.0.30+208`、**protocol version=1**、HTTP `/v1/send`、连接码 + roster |
| `docs/CLAWCHAT_EVALUATION.md` | 评估的是**同名不同项目**：`cbd/clawchat`→Cowchat、`ngmaloney/clawchat` Electron 前端、`alexrudloff/clawchat` P2P |

如果不把官方组织的真实形态写清楚，很容易把「名字相同」当成「依赖相同」，或者把本机 v1 的经验套到官方 v2 上——正是项目一直要防的「错误情报带偏团队」。

## 调研实据（`gh` API 只读，2026-11-06）

`clawling` 是 **Organization**（`CLAWLING PTE.LTD.`，2026-04-08 创建，45 followers，`public_repos=2`）。用 `type=all` 分页复核：只有 2 个仓库，无 fork / 可见 private / archived。

| 仓库 | 语言 | Stars / Forks | License | 最近推送 | 定位 |
|---|---|---|---|---|---|
| `clawchat-plugin-hermes-agent` | Python | 29 / 3 | MIT | 2026-11-04 | Hermes Agent ≥v0.12 的 ClawChat gateway 插件（排除 v0.20.3–0.20.6，建议 ≥v0.21.6） |
| `clawchat-plugin-install-cli` | TypeScript | 2 / 0 | MIT | 2026-11-03 | npm 安装器 `@clawling/clawchat-plugin-install-cli`，`--target openclaw\|hermes` |

**协议是 ClawChat Protocol v2 / WebSocket**，README 与 `docs/client-integration.md` 明写「The server owns the wire contract」，插件只是 peer client。`pyproject.toml` 的唯一运行时依赖 `websockets>=13,<16` 从依赖侧坐实了常驻 WebSocket 客户端形态。

`plugin.yaml`（`manifest_version: 1`、`name: clawchat`、`kind: platform`、`version: 0.14.0-125`）声明 **7 个 hooks / 55 个 tools**；六个 `skills/*/SKILL.md` + `skills/manifest.json` 与本项目能力卡规范同构。安装器仓库则托管 `skills/` 与 `livewares/` 两棵树，钉在 `skills-vX.Y.Z` tag，并有 `skills:check` / `livewares:check` / `skill-frontmatter.test.mjs` / `release-guard.test.mjs` 守线——和本项目「命令面由 `build_parser()` 生成 + `test_skill_manifest.py` 守漂移」是同一套治理思路。

### 一个现成的「观点需要实据」样本

官方 README 写「fifty-three `clawchat_*` tools」，`docs/reference/tools.md` 写「There are **55** tools」，而 `plugin.yaml` 实际声明 **55**；`tools.md` 自己也说 `plugin.yaml` 是权威清单。**散文数字不是证据，声明文件才是。** 文档同时记录了另三类混淆：同名不同项目、v1/v2/NDJSON 三个协议面、以及官方 `agent-protocol.md` 自己强调的「`hello-ok` 只证明通道连上，不证明宿主模型在回答」——与本项目「只有 `VERIFIED` 能关单」同构。

## 结论：不引入运行时，只引协议与工程规范

| 项目硬约束 | 官方插件要求 | 判定 |
|---|---|---|
| 库级无服务、无 DB、无后台线程 | 第三方服务端持有 wire contract + 常驻 WebSocket + Hermes/OpenClaw 宿主进程 | ❌ |
| 不新增 schema / `coord-*` 命令面 | 55 个 `clawchat_*` 工具、7 个 hooks、plugin.yaml、skills manifest | ❌ |
| 规则可复算、fail-closed | `--dangerously-force-unsafe-install` 绕过宿主安装期安全扫描 | ❌ |
| 单次有界、默认 dry-run | 插件是常驻 gateway，installer 会改写宿主配置 | ❌ |
| 只引协议不引运行时 | `agent-protocol.md` 的通道/宿主划分、具名错误目录、凭据边界 | ✅ |

可借鉴的具体点已逐条映射到项目文件：能力卡 + 生成 manifest + 守线、`atomic_file.py` 原子写、`gate_outcome.py` 具名拒绝、`instance-locks-and-install-conflicts.md` / `multiplex-profile-isolation.md`、`prompt-injection.md` / `tool-grants.md`、`secret-outputs.test.ts` 凭据不泄漏断言、`group_message_coalescer.py` 组内合并。
