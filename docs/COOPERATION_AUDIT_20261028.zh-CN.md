## 结论

AEP 当前已形成可运行的本地协作协议：工作区接入、任务认领、租约、检查点、证据接力、阶段事件监听、Windows 验证进程治理和受控恢复均已有实现，并通过本地测试与 GitHub Actions 矩阵。

系统仍未完成跨 WorkBuddy、Qoder、Hermes 等真实宿主的完整闭环。因此，代码测试通过不能被表述为真实 Agent 已收到、已读、已接单或已完成外部任务。

## 下一轮 P0 验收

选择一个真实在线 Agent，使用无害挑战消息完成以下顺序，并为每一步保存事件 ID、会话 ID、时间和原始回执：

1. 发现并唯一绑定已有会话；目标不唯一时停止。
2. 发送一次挑战消息，禁止默认新建会话。
3. 从同一会话读回消息。
4. 要求 Agent 返回唯一 ACK 串。
5. 由 Agent 认领一个低风险任务。
6. 生成一个可核验产物并回写 SHA-256。
7. 复核者检查产物、认领者和会话归属。

验收状态必须分别记录为 `CLIENT_BOUND`、`MESSAGE_VISIBLE`、`AGENT_ACK`、`CLAIMED`、`ARTIFACT_VERIFIED`。任何中间状态缺失都保持 `UNKNOWN`，不自动升级。

## P1 开发目标

- 为 WorkBuddy、Qoder、Hermes 各实现宿主适配器契约：`discover`、`bind_existing_session`、`send`、`read_back`、`challenge_ack`、`health`、`failure_classification`。
- 增加统一宿主验收报告，不把监听器 READY、窗口聚焦或输入完成误报为 Agent 接单。
- 将只能读文件的 Agent 转成代办请求，由具备命令能力的 Agent 执行，记录发起者与执行者的区别。
- 用状态机测试覆盖重启、重复事件、租约过期、结果未知和恢复竞争。
- 只在确定没有副作用的只读探测中使用有限重试；消息发送、上传和发布禁止通用盲重试。

## P2 目标

以可选适配器方式研究 A2A 能力卡和任务产物协议；用 DBOS/SQLite 验证本地持久步骤；用 Hypothesis 扩大状态机测试。Temporal 仅在多机部署有实际需求且完成运维评估后引入。核心继续保持无强制第三方运行依赖。

## 接力规则

后来加入的 Agent 先读 `AEP_JOIN.md` 和本文件，再运行 `route` 获取 `next_action`，读取当前 digest，确认任务未被占用后认领。代码推送前运行本地完整测试；推送后等待 CI；真实宿主验收另写回执。`.workbuddy-ai/`、令牌、聊天全文和本地状态不进入 Git。
