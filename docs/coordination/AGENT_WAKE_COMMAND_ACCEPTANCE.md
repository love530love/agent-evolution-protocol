# Agent 唤醒、发令与执行验收

## 一条订单的四个证据级别

1. **启动/定位**：进程或窗口存在，且绑定到唯一 PID、窗口和原会话。此状态不能称为送达。
2. **消息送达**：在同一会话的已发送消息区读回事件 ID；输入框里看见草稿不算送达。
3. **Agent 接单**：目标 Agent 自己回复 `AEP-ACK:<事件 ID>`，且回复方向、时间和会话身份均与订单匹配。订单正文中的 ACK 请求不算回执。
4. **任务完成**：产生可检查的产物或执行回执，经过对应的测试/审阅；ACK 不等于完成。

指挥消息只含事件 ID、任务目标、优先级和本地上下文入口。完整上下文由文件信箱承载。每个订单必须有幂等键、截止时间和失败熔断；静默期间不调用模型轮询，只在文件事件、客户端回执或用户指令到来时推进。任何传输失败都保留待办，不自动宣称完成。

## 新 Agent 接入流程

1. 登记名称、进程、可执行文件、窗口标题、工作空间及已有会话标识；先只读发现。
2. 选择一个**经过客户端授权**的通道：原生 API/CLI 优先；其次是明确会话的浏览器 DOM/UIA；视觉操作只能在识别并读回目标控件后使用。不同 Agent 可以有不同通道，不要求一个万能脚本。
3. 用无害的测试订单做一次真实投递。核验已发送消息、目标独立回复和事件 ID；失败即停，不自动重试不确定的写入。
4. 才允许该客户端参与自动派单。每次派单仍须带任务范围、优先级、可恢复上下文、停止条件和产物验收规则。

自动打开应用不等于可以绕过其权限或安全机制。不能定位唯一原会话时，状态为“待人工锚定”而不是另开会话；跨 Agent 并发操作同一桌面时实行独占输入租约，文件/API 通道则可并行。

## 当前安全闸门

- CDP 不再扫描端口后拿第一个页面发令。必须在客户端配置中绑定 `cdp_port` 和 `cdp_target_id`，有已锚定的目标窗口，并能确认监听端口属于该窗口进程或其亲子进程；归属不可查时回退到其他通道。
- CDP 消息读回排除输入框草稿；只有同一表单中存在唯一、可见的提交按钮才尝试提交。缺少此控件返回 `SUBMIT_UNVERIFIED`。
- 原始 OCR/DOM 全文中的 `AEP-ACK` 不算接单，因为它可能是我们自己发出的请求。只有明确标为 `assistant`、`incoming`，并且会话 ID、时间和事件 ID 均匹配的回复事件才会升级为 `AGENT_ACK`。现有通用 OCR 读取尚不能可靠标注消息方向，所以在该通道下 ACK 会保持待确认；这是有意的安全降级，不是已经完成无人值守闭环。
