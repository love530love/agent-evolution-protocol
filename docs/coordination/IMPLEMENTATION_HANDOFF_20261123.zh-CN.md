## 可并行攻坚与验收

### A. 工作区身份与加入

- 确定一个权威的持久映射：项目根/协调根与**已存在的**联邦 workspace state 绑定。定义第一次绑定、重新打开、迁移机器或目录、多个 workspace 候选、state 损坏和用户显式切换；歧义时返回候选及原因，不自行合并或生成新身份。
- 不破坏已有 `aep join` 和 `join-agent.ps1` 的兼容性：新增可审计的绑定查询/校验和显式登记路径，再将正常加入流程接上。成员来源/会话声明、实际在线、身份认证分别呈现。
- 验收：重复/并发加入只产生一次成员和事件；不存在的工作区、不同项目同名 Agent、路径移动、ID 冲突和重启恢复均有测试；不得把别人 presence 转成自己的成员声明。

### B. 群聊通知与信息索引

- 以 SQLite 中已有加入事件为可靠源，设计可恢复、幂等的 outbox 到协作 journal：为同一 join event 使用稳定消息 ID，写入后回读，故障后安全重试；不要在两个独立存储上宣称天然原子。读取游标按工作区和消费者持久化，记录读取行为与真实客户端收到分开。
- 新事件沿调用链携带已验证的 workspace ID；保留源事件、来源、时间和哈希。历史 unbound 继续单独查询；只有持明确证据的迁移才写入可追溯绑定，保留原始记录。
- 验收：模拟在 SQLite 提交前、提交后、journal 写入前后崩溃，重放无重复、不跨工作区；可重建索引的快照时间及源变更状态对用户可见。

### C. 唤醒、忙碌插话和证据

- 按 `workspace + provider + agent + session marker` 定位原会话，禁止将同名国内版/国际版合并。先只读发现与校准，再按已授权订单执行；使用会话租约与桌面输入互斥。忙碌时先按客户端能力确认可排队/插话；不确定则不自动中断模型。
- 将每个事件的 `SESSION_LOCATED → INPUT_SUBMITTED → MESSAGE_VISIBLE → AGENT_ACK → RESULT_READBACK → ARTIFACT_VERIFIED` 分开记录。ACK 须来自实际回复，关联同事件及已核验会话；不确定提交状态先 reconcile，不换通道盲重发。
- 编写缺 ACK 字段、错事件、错会话、陈旧证据、只写输入框、发送失败、重启后的在途状态等反例；再分别在至少两个不同厂商的真实原会话进行无破坏任务验收，保存可回读证据。

### D. 常驻与接力

- 分别观测 Core、Desktop、进程身份和会话证据，不以托盘图标或新鲜文件代替进程存活验证。保留用户现有托盘模式；只对明确归属 AEP 的子进程实施受控回收，PID 重用须校验创建时间。
- 保存用户最新有效指令、约束、当前任务 DAG、认领/租约、在途外部操作与未决证据；额度未知就标 unknown，按心跳/故障证据交接。切换执行者先恢复快照并处理未确定操作，避免重复副作用。
- 验收：在隔离测试环境故障注入进程退出、心跳超时、额度告警、人工修改需求与重启；至少一次真实不同执行者接力须记录谁接管、原任务状态、输出及核验，不依赖单个模型自报成功。
