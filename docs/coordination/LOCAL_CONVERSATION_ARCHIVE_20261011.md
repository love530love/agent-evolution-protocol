# 当前工作区本地会话档案（2026-10-11）

目标：用户分别与多个代理聊天时，已接入客户端收到的原始 Hook 载荷即使实时协作室离线也先落本地，其他代理按游标读取并确认。**本地原文不脱敏**，但档案目录被 Git 忽略，不得自动推送到远程或复制到其他工作区。

## 已实现

- Codex／WorkBuddy Hook：在工作区范围内对 `prompt`、`stop`、`start`、`end` 先写 `private_conversations/events/*.json`，保留抽取的全文与 Hook 原始 JSON，再尝试实时镜像。协作室不可达不丢本地事件。
- `aep --coord-root <协作目录> coord-chat-read --agent <代理> --limit 50`：读该代理尚未确认的事件；`--include-raw` 可取原始 Hook 载荷；`--after <事件ID>` 可指定游标。
- `aep --coord-root <协作目录> coord-chat-ack --agent <代理> --through <事件ID>`：确认读到的最后事件；游标不能后退或指向不存在的事件。
- 无 Hook 的客户端可以 `coord-chat-publish --source <代理> --role user|assistant --text-file <UTF8文件>` 主动导入。此途径不等于自动采集。
- Agent 加入工作区的首批命令包含 `coord-chat-read`。静默时无模型轮询；有新事件时本地文件变化可供外部通知器使用，但通知器不能冒称目标模型已读。

## 未覆盖及边界

- “原始 Hook 载荷”不一定等于客户端完整私有聊天历史。若客户端只提供本轮输入或最后一条回复，未提供的中间消息无法凭本模块补全。Qoder、Copilot、Hermes 等须逐一验证原生 Hook/API/导出权限。
- 该档案暂未提供跨机器复制、加密静态存储、自动保留期、全文索引或可靠的客户端内原会话唤醒。文件权限沿用当前用户账户；本地不脱敏意味着应保护工作站和备份。
- `ACK` 仅代表某个协作者确认读到事件，不代表采纳、执行或完成。用户的跨会话新指令必须在后续写入、上传前由执行者核对；现阶段尚未强制接入所有外部写入入口。
- 普通聊天事件不自动启动 agent。显式 `@wake` 仍走原有唤醒授权和接单回执；不得因档案里出现一条指令就在别的应用自动输入。
