# 浏览器任务的能力路由与降级契约

目标是让每名 Agent 先发挥自己**已经验收**的浏览器能力；没有相应能力或当前连接失效时，才借用 AI Browser Bridge。路由依据是当前任务所需动作的证据，不是 Agent 的名气、偏好或上次成功的印象。

## 选择顺序

1. **本 Agent 的内置浏览器**：仅当它能在当前授权页面完成所需的读取、选择、上传或提交动作，而且本轮已确认工具可用时优先。保留原会话、原标签页和用户已选模型。Qoder 的内置浏览器“可能较好”是用户观察；本仓库尚未完成可复核的能力验收，不能预置为已通过。
2. **AI Browser Bridge**：内置浏览器缺少某项能力、连接失败或经一次诊断确认不适用时启用。先按其本机 quickstart 检查服务/扩展连接、获取工具列表，再读取目标标签页和页面状态；不要仅凭历史版本号或 `connected` 推断本轮动作可行。自定义下拉优先结构化 `browser_choose`，允许目录中的文件上传优先 `browser_upload`，具体可用性以本轮工具清单为准。
3. **经验收的桌面 UI 兜底**：前两层不可用时，只能在目标窗口、会话、控件和提交状态均可唯一确认的条件下使用；否则停在可恢复状态，请求人工处理。坐标、上次滚动位置、盲按键不是已验收能力。

每一层都按动作而非整场任务路由。例如内置浏览器能读取但不能上传时，仅上传一步转交 Bridge；转交时附当前页面 URL、目标标签页、已完成步骤、未完成动作与是否可能已经提交。多 Agent 共享同一浏览器时，先取得现有协作租约或明确独占窗口；读操作可并行，写操作不得抢占。

## 每次动作前的最小核查

- 确认用户授权的站点、窗口/标签页及当前会话；读取实时页面，定位目标元素并确认它唯一。
- 查询当前工具清单或实际探针，确认“读、选、传、提交”分别由哪个工具执行。工具存在不等于该站点已授权或控件可操作。
- 记录本轮任务 ID、动作 ID、提交包路径及哈希、页面或回表证据。上传前检查文件确实存在，且 Bridge 的上传根目录允许该文件。
- 提交、删除、发布等外部写操作前，先确认未发生同一动作；写后读取页面/服务端结果。结果不明时保持 `UNCERTAIN` 并交给核查流程，不自动重放。

## 失败后的引导重试

| 失败类型 | 下一步 | 禁止事项 |
| --- | --- | --- |
| 工具未发现、扩展未连接或页面未授权 | 重新读取连接与权限状态；改用下一层已验收通道 | 把旧会话的 `connected` 当成本轮凭据 |
| 控件 ref 过期、下拉重渲染 | 重新读取页面，取得新 ref，核对候选文本后再选 | 重用旧 ref 或旧坐标 |
| 上传对话框没有出现、输入注入失败 | 确认页面、文件 input 和当前窗口；优先结构化上传 | 反复点击造成叠窗，或把选中文件误报为已提交 |
| 提交后无确认或超时 | 只读核查提交记录、页面提示和回表；标记不确定并移交 | 再次提交相同包消耗额度 |
| Agent 工具能力不足 | 用协作信箱把具体动作、证据和原会话交给具备能力的在线队友 | 因工具不足新建无上下文会话或声称任务完成 |

读回分三层记录：`已操作控件`、`页面确认成功`、`服务端/回表确认成功`。它们不可互相替代。若页面状态发生变化，应重新规划下一步，而不是继续执行旧脚本的剩余坐标。

## 新 Agent 的接入提示

> 浏览器任务先检查你自己的内置浏览器是否能完成本轮所需动作；能且已经实际验收就优先用它。缺能力或连接不可用，再按 AI Browser Bridge quickstart 检查连接、列工具、读页面并操作。保留原会话和标签页；任何外部写操作结果不明都先核查，不要重发。将本轮有效/失效工具、页面证据和经验写入共享协作记录，供其他 Agent 复用。

这是一份路由契约而不是对所有客户端能力的保证。客户端版本、权限和站点布局变化后需重新验收；没有证据时标记“待验收”。
