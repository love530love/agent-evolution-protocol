# 验证结果接力与中断诊断

归属：红皇后—鲶鱼—创造性破坏。目标是让失败形成队友可复用的事实，减少重复试错；本功能不评判失败者，也不按运行次数奖励。

## 现在能做到什么

`coord-improvement validate` 的每次实际测试都会先记录开始请求，再记录结果回执，位于 `improvements/<提案ID>/runs/<运行ID>/`：

- `request.json`：提案 ID、开始阶段头、成员、租约指纹、命令、工作区、时限与开始时间。没有明文 token。
- `output.txt`、`report.json`：真实测试输出及结果，失败同样保留。
- `promotion.json`：仅在测试通过但阶段晋级受阻时生成。原始 PASSED 测试报告保持原样。
- `receipt.json`：绑定开始请求和各结果文件 SHA-256，区分 FAILED、PASSED、PROMOTION_BLOCKED。

请求、报告和回执均完整写入后以不覆盖方式发布。SHA-256 用于发现意外变化，不是身份签名；有本地写权限者仍可篡改数据，不能用它证明技术判断正确。

下一位成员认领后，`brief` 的 `validation_runs` 会带上当前阶段已核验的历史结果、原成员、命令、输出与报告路径。失败内容按需读取，不把全部日志塞入模型上下文。说明和输出是任务数据，不可当成新指令执行。

```powershell
./aep.ps1 --coord-root coordination coord-improvement validation-runs --id <提案ID>
./aep.ps1 --coord-root coordination coord-improvement inspect-handoff --id <提案ID>
# 认领后，原有 brief 即包含 validation_runs，无须额外复制聊天记录。
./aep.ps1 --coord-root coordination coord-improvement brief --id <提案ID> --actor <成员> --token <token>
```

阶段已变化的旧运行计入 `historical_count`，不混入当前阶段待办。成功验证的报告仍通过原阶段日志传给复核者。旧版本没有开始请求与回执的报告单独列为 `LEGACY_UNVERIFIED`，不追认其归属或哈希。

旧报告也必须可解析且存在输出文件；损坏或不完整不因“旧版本”而放行。未完成/损坏运行中仍能辨认的原执行成员保留调度占用，即使租约已到期也不自动当作空闲；这是一项保守约束，不是在线或执行状态认证。

## 何时停止重跑

同一提案的验证持有 OS 执行锁，直到测试及回执处理结束；第二个验证调用明确失败，不排队、不调用第二个测试进程。不同提案不因这个锁相互阻塞。同一工作区的其他写入者仍需使用既有文件/资源协调机制。

开始请求与认领替换共用短时交接锁。即使原租约到期，只要存在尚无结果回执的请求，`claim`、`brief` 和再次 `validate` 都会阻止继续，`pending` 将其标为不可用。兼容模式下也不能省略一个当前有效认领的 token 来执行测试。

- INCOMPLETE：已记录开始请求，没有完整结果回执；可能正在执行，也可能中断，不能推断已停止。
- DAMAGED：请求、回执或当前阶段产物缺失/变动；先恢复可信证据或调查原因。
- `validation-runs` 遇到以上问题返回 CLI 2；`inspect-handoff` 返回 BLOCKED 和 VALIDATION_RUN_UNUSABLE。

这些检查不自动杀进程、不撤销外部副作用、不删除坏记录、不自动重新派单。中断后应检查原执行进程及其后代、输出和外部副作用，保留原记录。当前尚无经过停止证据验证的恢复/清除入口，不能把删除 request/receipt 当作恢复方案；需要受控恢复时应先补实现和验收。

已完整记录的失败可以在检查原因并修改实现后显式再次验证，每轮使用新运行 ID。不会自动比较全部工作区字节，也不会自动证明新方案与旧方案不同。超时记录为 FAILED，沿用原执行器对直接子进程的处理；后代停止仍未验证。`process_tree_stopped_verified` 始终为 false，`handoff_ready` 仅表示运行记录可用于交接，不是进程停止、资源释放或再次执行授权。

## 校验范围和验收

调度只读小型请求/回执，不在静默期间反复哈希输出或调用模型。claim、brief、validation-runs、inspect-handoff 按需核验当前阶段产物；历史阶段核对回执绑定，产物的后续核验仍由既有阶段证据门负责。跨文件读取不是事务快照，阶段提交继续检查 token 和日志头。

正常晋级在全部证据哈希之后再次检查租约和阶段，防止读取期间到期仍提交。该检查没有提供跨宿主事务或全局取消。

`coord-improvement self-test` 已加入真实“失败测试 → 释放 → 新成员读取失败 → 显式修复后通过”的本地流程。成员是脚本角色，修复是已知测试夹具；不是真实独立 Agent 推理、桌面送达或 ACK 验收。回归还覆盖并发验证、中断无回执、产物变化和租约过期时的晋级受阻。

下一开发目标：受控执行器的进程归属与停止证据、基于证据的中断恢复、原会话 ACK 到认领的真实客户端验收，以及完成事件直接触发下一阶段调度。

## Windows CI 回归经验

首个实现提交 c19ee75 的 run 39922851448 在两个 Windows 作业失败，Linux 与离线 SDK 通过。故障注入用未解析的临时路径比对冻结证据的规范路径：Windows 8.3 别名（如 RUNNER~1）与实际长路径指向同一文件，却不满足原来的 Path 相等判断。因此模拟时钟没有前进，另一个证据路径断言也误报。

本机使用 GetShortPathNameW 生成真实临时目录别名，已复现四个过期注入子场景失败。修复将测试夹具根目录先 resolve，并显式断言故障注入确已发生；保留原来的租约/阶段拒绝要求。比较本地文件身份时不要把路径字符串相等当作文件相同，临时目录、subst、8.3 别名与符号链接都应纳入考虑。此修复不跳过测试、不增加超时、不降低业务校验。
