# 初学者介绍：为什么多 Agent 越协作，反而可能越平庸？

## 一句话说明

Agent Evolution Protocol 不是让更多 Agent 一起聊天，而是让它们先保持独立判断，再通过可审计实验竞争，最后才协作执行。

它试图解决这样一个反直觉问题：

> Agent 数量增加、消息变多，不等于独立思考增加。大家过早共享方案后，可能只是用不同措辞重复同一个错误。

## 一个具体例子

假设要优化一段程序，安排三个 Agent：

- Agent A 首先提出“增大分块尺寸”；
- Agent B 看到 A 的结论后，建议“稍微调整分块尺寸”；
- Agent C 总结两者，给出“综合分块方案”。

表面上有三位专家，实际上只有一条路线。若第一个假设错了，三者很可能一起错。

本协议会改成：

1. 三个探索单元先分别工作，暂时看不到其他候选的假设；
2. 每个单元写下唯一假设、预测、最低成本证伪实验、预算和停止条件；
3. 只公开这张卡片的 SHA256，证明之后没有改答案；
4. 全部提交后同时揭示；
5. 每条合格路线先获得一次便宜的证伪实验；
6. 明确失败的淘汰，有信号的再获得预算；
7. 最终由可复现实验而不是投票选择方案。

这就是 `commit → reveal → falsify → select`。

## 设计初衷

### 1. 保护认知差异，而不是追求 Agent 数量

多个 Agent 的价值来自不同搜索路径。如果它们拥有相同模型、相同上下文、相同提示和相同先验结论，它们更像一个意见的多次采样，而不是独立专家。

因此协议记录污染关系，不把多人格、重复采样或互相看过答案的 Agent 自动算作独立证据。

### 2. 共享事实，但暂缓共享候选推理

并非所有信息都应该隔离。

立即共享：

- 正式规则和安全告警；
- 基线、环境和工件 SHA；
- 预算余额和任务 ownership；
- 已验证的实验结果。

commit 前保持隔离：

- 根因假设；
- 实现路线；
- 参数搜索策略；
- 对竞争方案的评价。

这形成两个平面：协调平面负责合作，竞争平面负责保持探索差异。

### 3. Leader 负责行动，不垄断真理

复杂任务仍然需要一个负责人，否则预算、期限和集成会失控。但 Leader 的权力被限定为：定目标、拆任务、分预算、排顺序和承担最终责任。

Leader 不能仅凭身份宣布技术正确，也不能同时成为候选作者、唯一裁判和最终批准者。

### 4. 保留异议权，但不给异议无限权力

“鲶鱼”不是为了反对而反对。有效挑战必须说明：

- 它挑战哪个假设；
- 有什么结构不同的替代解释；
- 两条路线会产生什么不同信号；
- 最便宜的证伪办法；
- 最大预算和停止条件。

鲶鱼每轮可以获得一张受保护的小额实验票，但不能绕过安全规则、无限阻塞或给失败路线反复续命。

### 5. 让证据分配资源

本协议不通过“多数 Agent 同意”决定技术胜负。候选先过合规、身份、SHA、复现和预算门槛，再按以下顺序竞争：

1. 正确性与合规；
2. 是否解决预登记根因；
3. 真实环境覆盖；
4. 主指标增益；
5. 稳健性；
6. 预测校准；
7. 信息增益/成本；
8. 可复现性。

结果在误差范围内时应写 `INCONCLUSIVE`，而不是强行选赢家。

### 6. 静默时零模型轮询

“常驻鲶鱼”指制度上始终保留挑战通道，不代表后台模型一直运行。

普通消息只记录和送达。只有显式按钮、严格唤醒指令、特定事件或人工批准才允许启动执行。这减少 token 消耗，也防止普通讨论意外触发高成本行为。

### 7. 用审计代替“相信 Agent 自报”

每条事件包含序号、上一条事件 SHA 和自身 SHA。`audit` 可以发现历史覆盖、断链或篡改。

但哈希链只证明记录完整性，不证明某个结论真实。真实性仍需原始证据、可复现命令和独立评测。

### 8. 不可逆操作由人类控制

当前版本是 shadow 工具。它不会自动调用模型、运行 GPU、修改候选代码、合并分支或提交外部平台。

`HUMAN_HOLD` 和 `INCIDENT_HOLD` 会阻断后续候选动作；恢复必须明确带有人类批准标记。

## 三个名称分别代表什么

### 红皇后

来自“必须持续奔跑才能留在原地”的竞争隐喻。系统需要感知真实的规则变化、对手突破、环境升级和方案失效。

这里的关键是“真实”：外部威胁必须带来源、时间、可信度和最低成本确认方式。传闻不能自动消耗高成本资源。

### 鲶鱼

代表内部扰动者。它在集体过早一致、路线高度相似、连续重复失败或主路线占用过高预算时被事件唤醒。

它的任务不是赢，而是用低成本关闭重要盲区。

### 创造性破坏

旧路线不会因为投入很多、领导支持或叙事漂亮而永久保留。实验可以淘汰它，资源随后转移给更有证据的新路线。

协议本身也不例外：如果它不能改善结果，就应该被简化或替换。

## 背后的管理学和经济学理念

- **分散知识**：局部单元掌握不同信息，不应把所有知识压缩成一个中央意见。
- **多中心治理**：不同探索岛可以局部自治，同时接受共同边界、监测、申诉和渐进制裁。
- **探索—利用平衡**：一部分预算发展领先路线，一部分预算寻找结构不同的新路线，并保留恢复储备。
- **实物期权**：小额证伪票是在购买未来选择权；失败损失有限，成功后再扩大投入。
- **委托—代理与制衡**：Leader、Evaluator、Integrator 和 Safety Guardian 必须职责分离。
- **Goodhart 风险**：任何单一指标成为目标后都可能被投机，因此采用多维指标，并审计指标本身。
- **预测校准**：候选不仅给结论，也给可检查的预测；长期比较“有多自信”和“实际多准确”。

## 一轮任务如何运行

```text
用户/Leader 定义任务、预算和成功标准
                  │
       ┌──────────┼──────────┐
       ▼          ▼          ▼
   探索岛 A    探索岛 B    鲶鱼岛 C
   私下形成     私下形成     结构性替代
   候选卡       候选卡       候选卡
       └──────────┼──────────┘
                  ▼
          全部 commit 哈希
                  ▼
             同时 reveal
                  ▼
       资格检查与最低成本证伪
                  ▼
          同环境、同预算评测
                  ▼
        主胜者 + 差异化备选
                  ▼
       Leader 写决策回执并集成
```

## 初学者第一次试用

安装开发版本：

```powershell
python -m pip install -e .
```

初始化影子回合：

```powershell
python -m agent_evolution_protocol init `
  --round-id demo `
  --task example `
  --leader lead `
  --cells alpha beta catfish `
  --budget 10
```

复制 `templates/proposal.json` 为三个候选文件，分别修改 `candidate_id`、`cell_id` 和假设内容，然后依次执行：

```powershell
python -m agent_evolution_protocol commit --round-id demo --card alpha.json
python -m agent_evolution_protocol commit --round-id demo --card beta.json
python -m agent_evolution_protocol commit --round-id demo --card catfish.json

python -m agent_evolution_protocol reveal --round-id demo --card alpha.json
python -m agent_evolution_protocol status --round-id demo
python -m agent_evolution_protocol audit --round-id demo
```

运行数据默认写在 `.agent-evolution/`。这些命令只操作本地 JSON/JSONL 文件。

## 初学者常见误解

### “是不是 Agent 越多越好？”

不是。低风险、明确任务用单 Agent 更快。只有高不确定、可拆分、路线可能不同的任务才值得启用多个探索岛。

### “是不是故意不让 Agent 沟通？”

不是。规则、安全、基线和已验证结果应立即共享；只是候选假设在 commit 前暂缓共享。

### “鲶鱼是不是拥有否决权？”

没有。它拥有一次有上限的证伪机会，最终仍由证据决定。

### “哈希链能证明结果正确吗？”

不能。它只能证明记录后来没有被悄悄改写。正确性需要实验和证据。

### “可以直接接管生产系统吗？”

不建议。先做历史盲回放，再做低风险旁路试点，最后才考虑接入执行系统。
