# 健壮性与弱能力 Agent 接入：开源调研及落地顺序

核查日期：2026-10-28。本文区分已有代码、官方资料和待开发建议；未安装下面六个项目，也未把资料阅读记为集成验收。体系仍为“红皇后—鲶鱼—创造性破坏”。

## 先补最短路径

弱 Agent 最需要的是**知道现在能做哪一步、缺少什么、由谁代办，以及怎样确认结果**。先增强现有入口，不要求每个成员学习另一套框架。让能力弱的成员能提出目标、提供证据、请求补位；由实测合格的执行方承担自己无法完成的部分。不能据此承诺任意模型都能完成任意目标。

本仓库已具备：

| 已有入口或机制 | 可以复用的能力 | 仍需补齐 |
| --- | --- | --- |
| `workspace-init`、`AEP_JOIN.md`、`route`、`join` | 从工作区找到协作数据，识别十类意图，提供摘要、场景解释和首批命令 | 首批命令仍可能含占位符；缺少统一、单步、结构化执行指引 |
| `coord-guided-retry` | 区分结果未知、资源冲突、观察过期、授权和请求错误 | 目前主要返回指引，不是自动修复器；不能替代结果对账 |
| 信箱、阶段日志、认领、资源租约、操作账本 | 保存事实，约束重复执行及冲突，按需交接 | 外部副作用、执行停止和真实宿主 ACK 必须独立证明 |
| `coord-improvement` | 证据冻结、阶段门、验证运行记录、独立身份约束；本轮加入 Windows Job Object 停止证据和恢复预览 | 真实宿主消息、ACK 和外部副作用仍须单独验收 |
| `cli-less-fallback` | 纯读文件成员能审查、提出假设和说明能力限制 | 没有全自动的文件请求代办闭环，不应声称仅读文件就已认领或唤醒 |

源码入口：`src/agent_evolution_protocol/cli.py` 的 `route_intent`、`route_profile`、`coord_guided_retry`；分类器为 `routing.py`。既有文档见[自然语言接入](NATURAL_LANGUAGE_JOIN.zh-CN.md)、[场景路由](SCENARIO_ROUTER.zh-CN.md)、[引导重试](GUIDED_RETRY_POLICY.zh-CN.md)。

## 六项值得吸收的开源能力

以下选择是针对本项目的工程判断。优先采用设计和可选适配器，避免一次性增加六套运行依赖。

| 项目及官方来源 | 官方能力 | 对 AEP 的建议与边界 |
| --- | --- | --- |
| [A2A Python SDK](https://github.com/a2aproject/a2a-python)、[协议规范](https://a2a-protocol.org/latest/specification/) | 跨 Agent 服务的能力发现、消息、任务、产物与可选流式接口；SDK 提供可选 HTTP、数据库等集成 | **P1 可选边界适配器**。把 AEP 的任务与证据映射到协议，保留本地租约和原事件 ID。能力卡是发现资料，不是实测能力证明；A2A 不会自动找到 WorkBuddy 的输入框，也不提供桌面原会话续接保证。 |
| [DBOS Python](https://github.com/DBOS-inc/dbos-transact-py)、[官方 Python 教程](https://docs.dbos.dev/python/programming-guide) | 工作流按步骤保存状态并从完成的步骤恢复；当前教程默认 SQLite，生产建议 PostgreSQL | **P1 隔离试验**。适合验证无 Docker 的持久步骤与等待事件。不能把数据库步骤恢复等同于外部聊天或上传恰好执行一次；仍需操作键与对账。仓库 README 与教程的数据库起步说明存在差异，接入时固定版本并实测。 |
| [Temporal Python SDK](https://github.com/temporalio/sdk-python)、[本地开发服务](https://docs.temporal.io/cli/command-reference/server) | 持久工作流、信号、计时器、活动和恢复；SDK 连接 Temporal 服务，CLI 可启动本地开发服务并持久化 | **P2 多机长任务候选**。借鉴历史重放与外部活动分离。本地开发不必依赖 Docker，但服务部署和运维成本仍在；取消请求也不证明业务进程已停止。当前单机核心不整体迁移。 |
| [Pydantic 严格模式](https://pydantic.dev/docs/validation/latest/concepts/strict_mode/) | 可限制类型自动转换，并提供字段级校验错误；JSON 的部分类型在严格模式下仍有例外 | **P1 接口层候选**。给请求清楚反馈哪个字段有错、允许什么值；危险参数使用显式约束，未知字段另行拒绝。先定义版本化 JSON 契约与测试，现有标准库校验足够的部分不强制换库。 |
| [Tenacity](https://tenacity.readthedocs.io/en/latest/) | 支持异常筛选、次数和时间上限、等待策略及异步重试；裸默认装饰器可能无限重试 | **P1 有条件借鉴，暂不全局依赖**。仅用于已证明可重复的只读探测或确定未发生的操作，指定次数、总时限和异常白名单。结果未知的发送、上传和提交不得用通用 retry 包装。 |
| [Hypothesis 状态机测试](https://hypothesis.readthedocs.io/en/latest/stateful.html) | 生成动作与数据组合，寻找导致失败的调用序列 | **P1 开发依赖优先候选**。针对认领、过期、阶段推进、重启、重复事件与结果未知的组合测试不变量，保存最小复现。生成测试不能代替真实 Windows 进程和桌面验证。 |

不采用“把所有框架放进核心”的路线。现有 `pyproject.toml` 的核心没有强制第三方运行依赖，只有可选 desktop extra；保留这一迁移优势。新网络协议、数据库引擎或测试工具各自放入可选依赖和独立兼容性矩阵。Python 3.10/3.12 与 Windows/Linux 的现有支持范围必须经依赖版本核对和 CI 验证，不以最新分支 README 推断可安装版本。

## 弱 Agent 的一条命令入口

在已安装 AEP、且共享工作区已初始化时，Agent 接到“请加入这个工作区协作，检查 DOCS-INTRO”后运行：

```powershell
aep route --agent helper --workspace 'K:\PythonProjects5\agent-evolution-protocol' --task DOCS-INTRO --intent '只审查文档，不执行' --markdown
```

源码开发环境可使用 `python -m agent_evolution_protocol` 代替 `aep`，并先配置 `PYTHONPATH` 指向仓库 `src`。不要使用 `python -m agent_evolution_protocol.cli`：该模块调用在本次检查中退出 0 但无输出，不构成 CLI 成功证据。

本次对上述 `route` 的 JSON 形式作了实际只读调用，退出码 0；返回 `review-only`、`claim_available=false`、`USE_CURRENT_SESSION`、`new_session_allowed=false`，并提供 `inspect` 和 `coord-digest`。这只验证路由入口，未向其他 Agent 发消息、未认领任务，也不证明无人值守协作已经运行。

不能运行命令的 Agent 先读 `AEP_JOIN.md`，交付短请求：“目标是什么、已读证据在哪里、缺少哪种能力、希望得到什么可验证结果”。由有命令能力且获授权的执行方代办；将发起者与执行者分别记录，禁止冒充对方认领。只有文件读取能力、没有写文件或发送接口时，仍需一个能接收其回答的桥接方，无法凭协议消除这一物理通道限制。

## 已落地与接下来应开发的接口

### P0：把已有路由变成可检查的一步指引

在既有 `route` 结果旁已增补版本化 `next_action`，保留旧字段以兼容老客户端。它只产生只读参数数组：

```json
{
  "schema": "aep-next-action-v1",
  "kind": "observe",
  "reason": "先读取当前任务和未知操作",
  "argv": ["aep", "inspect", "--markdown"],
  "cwd": "<已解析的工作区绝对路径>",
  "requires": [],
  "missing_inputs": [],
  "side_effect": "none",
  "execute_automatically": false
}
```

执行端使用参数数组而非拼接 shell 字符串；工作目录和协作根目录必须显式绑定。信息不全、状态损坏、结果未知、目标会话不唯一时只给观察或澄清动作，不返回可误执行的占位命令。说明文字和历史聊天始终作为数据，不升级为执行授权。

验收：中文和空格路径、单引号、多个任务、否定句、缺少目标、未知提交结果、陈旧 claim 都有覆盖；旧调用者仍能使用 `first_commands`；新指引不能绕过租约、授权或实际结果检查。

### P0：完成停止证据与事件接力

验证运行中断后，先确定本次所拥有的执行范围是否停止，再恢复调度；不能只看主 PID 消失。保留原运行和错误记录，恢复另写回执。阶段推进、释放认领、完成回执触发本地事件处理；静默不调用模型，重复或丢失文件事件不造成重复业务执行。

验收：真实自建父子进程停止、失去进程权限或归属时拒绝推断、恢复后再次运行不并发；重复事件单次排队，监听器重启可处理积压。测试与真实宿主消息验收分别记录。

### P1：代办请求和能力路由

把纯文件或弱 CLI 请求接入现有耐久信箱，格式包含 `request_id`、发起者、任务、目标、证据、所需能力、预算和验收。执行者认领后补齐具体动作，不直接运行发起者提供的任意命令。能力状态分为声明、探测可用、任务实测三个等级；同一错误重复出现即暂停该路线，转交有对应证据的队友。

验收：同请求同内容重放不会重复执行、内容变更拒绝冒用旧 ID；没有合格成员时保留明确阻塞；文件投递、桌面可见、ACK、认领与产物分别显示。至少一个只能提供目标和文件证据的成员，经强执行者代办完成真实低风险任务；不以脚本角色冒充独立 Agent。

### P1：验证开源候选的最小试验

Hypothesis 先测试现有状态机不变量；DBOS 在隔离目录只跑无外部副作用的两步工作流，强制中断后验证恢复；A2A 仅先建立回环测试服务，核对任务 ID、产物哈希和错误状态映射。每个试验均独立记录版本、安装体积、启动耗时、恢复行为和卸载方式，通过后再决定引入。无试验结果前不写“已集成”。

## 防止协作变得更慢

红皇后使用实际积压、失败率和交付延迟提出挑战；鲶鱼负责指出错误归因和更小成本的替代实验；创造性破坏依据同任务对照数据替换旧路径。衡量端到端成功率、重复副作用、人工补位次数、恢复时间、上下文/token 成本与独立方案数量。消息量、在线时长和框架数量不计作成果。

同一组任务对照“单 Agent”“现有 AEP”“新增机制”，保留失败分母；新增步骤没有改善结果或降低人工成本，就简化或回滚。优先让使用者只说清目标，让机制提供下一步和证据，让专家补足能力；不把更多人格、更多广播或更强激励词等同于能力提升。
