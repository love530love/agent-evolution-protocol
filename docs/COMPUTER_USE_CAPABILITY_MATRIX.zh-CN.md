# Computer-use 能力矩阵与兜底

## 能力覆盖

| 层 | 可执行能力 | 首选 | 兜底 |
|---|---|---|---|
| 浏览器 | 打开页面、读取 DOM、填写表单、点击、上传、读取回执 | Agent 内置浏览器 / CDP | UIA、OCR、人工确认 |
| Windows 桌面 | 找窗口、控件树、文本输入、快捷键、截图 | UI Automation | OCR/剪贴板、可视化 Agent |
| MCP 桌面 | 工具发现、schema 校验、按名称调用 | 已探测 MCP provider | UIA/CDP |
| 终端 | PowerShell、Python、Git、构建、测试 | 受管工作区执行器 | 文件信箱交接 |
| 文件 | 读写、校验、打包、证据归档 | AEP 文件接口 | Agent 自带工具 |
| 协作 | 唤醒、发送、回读、ACK、重试、接力 | 原会话适配器 | 文件信箱 |

## 自动选择规则

1. 先使用目标 Agent 自带能力；
2. 再使用已授权且已探测的 CDP/UIA/MCP provider；
3. 再切换到同类能力的其他 Agent；
4. 最后写入文件信箱并等待具备能力的队友接力。

能力声明不等于可用。只有完成 `probe` 或真实任务验收的 provider 才能进入优先队列。

## 人类工程师级闭环

每个电脑任务都必须包含：目标定位、前置状态截图/读取、动作、动作后回读、错误捕获、重试上限、结果证据和归档。坐标盲点、重复点击、未确认的输入框、幽灵窗口和新会话漂移都视为失败信号，自动换通道或转交其他 Agent。

## 不可绕过的边界

AEP 不绕过登录、验证码、系统安全确认、第三方平台授权或用户明确的访问控制。开放委托模式可以让 Agent 自行承担审计和执行责任，但仍必须使用合法可用的接口和凭据。

## 验收标准

“完成”必须意味着目标状态已回读并有证据，而不是仅仅调用了点击、输入或发送函数。任何通道失败，都要保留错误并让调度器选择下一条路径。
