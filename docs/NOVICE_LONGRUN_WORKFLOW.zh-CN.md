# 小白用户的一句话长任务工作流

## 目标

用户只需描述目标、截止时间和限制，AEP 应生成任务图、选择 Agent 军团、分配阶段、
保存检查点，并在无人值守期间继续执行；用户不需要逐个催促 Agent 或搬运上下文。

## 统一入口（设计契约）

```text
启动长期任务：<目标>
截止：<时间>
工作区：<目录>
限制：<预算/禁止操作/必须人工确认项>
交付：<文件、报告、提交或部署目标>
```

调度器应将其转换为：

1. `mission_id` 与阶段 DAG（研究、实现、验证、审查、交付）；
2. 每阶段的能力要求、候选 Agent、预算和完成证据；
3. 每个阶段的 checkpoint、回滚点和接力条件；
4. 唯一 `event_id`、ACK lease、超时恢复与 dead-letter 策略；
5. 用户只收到“需要决策、发生阻断、阶段完成、最终交付”四类通知。

### 每轮工作的第一步：信箱分诊

任何 Agent 在接入工作区、恢复长任务或开始下一轮之前，先读取自己的定向信箱；
`urgent`/逾期事项优先处理。信箱分诊是按需动作，不是静默轮询。文件存在只代表
可恢复投递，必须继续取得同一 `event_id` 的 ACK、产物和独立验证，才能推进阶段。
详见 [信箱优先与情报闭环](MAILBOX_PRIORITY_AND_INTELLIGENCE_LOOP.zh-CN.md)。

## 无人值守验收

不能以“唤醒命令已发送”作为成功。连续运行必须满足：

- 每一阶段都有可恢复状态和最后一次事实快照；
- Agent 离线时可由备用 Agent 认领，不能重复执行高风险副作用；
- 机器重启、窗口漂移、登录失效后能进入明确的 `blocked` 状态；
- 任务完成必须有 artifact、校验摘要和 provenance；
- 失败超过上限进入 dead-letter，并只通知用户一次。

## 当前状态与边界

AEP 已具备唯一会话注册、多 transport 路由、ACK lease、失败恢复和桌面定位基础。
真正的“一句话启动多天任务”还需要上层 mission planner、持久化 DAG runner 和
通知策略接入；在这些组件完成前，不应向小白用户承诺完全无人值守交付。
