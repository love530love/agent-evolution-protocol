# 持久联邦 Agent 工作区引擎｜项目宪章

## 愿景

用户只需提交一次自然语言目标，系统就能在一个稳定的逻辑工作区内调度异构 Agent，
跨进程、跨模型、跨重启持续推进，直到交付物通过验收。工作区拥有任务状态、情报、
分工、快照和审计记录；Agent 是可替换、可接力的执行者，而不是状态的唯一载体。

## 五条架构公理

1. **Workspace 是唯一持有者**：每个任务绑定唯一 `workspace_id`，所有事件、消息、工件、
   会话绑定和快照都带水印；Agent 会话丢失不应丢失任务。
2. **A2A + MCP 优先**：A2A 负责异构 Agent 的发现、派工、回执和状态同步；MCP 负责工具、
   浏览器和本机资源；适配器负责翻译，不能把厂商私有会话当作公共状态源。
3. **职责分层**：资源底座只执行被授权的工具调用；联邦内核负责工作区、DAG、队列、唤醒、
   快照和恢复；业务 Agent 负责推理与产出；诊断 Agent 和策略进化 Agent 负责复盘与改进。
4. **快照优先接力**：接力传递结构化快照，而非无限复制聊天全文。快照分为只读锚定区、
   状态 DAG 区、情报摘要区和归档工件区。
5. **证据优先**：文件写入、窗口可见、输入提交、Agent ACK、产物回传和独立验证是不同状态，
   不能互相冒充。

## 必须具备的系统能力

- 工作区创建、持久化、重启恢复和浏览器会话复用；
- 任意已注册 Agent 的能力发现、原会话唤醒、优先级排队和并发隔离；
- Token 耗尽、进程退出、卡死、资源失败、冲突和外部干扰的诊断与接力；
- 旧执行者只读归档，新执行者基于快照接管；
- 每次故障、接力和冲突都进入策略进化流水线，验证过的策略才能晋升全局库；
- 事件、消息、快照、工件和回执可追溯、可复核、可回滚。

## 运行边界

浏览器/桌面底座不做任务决策；上层联邦内核负责工作区隔离、授权、资源配额、审计和停止条件。
底座可以提供完整操纵能力，但“能力可用”不等于“事件已送达”，更不等于“Agent 已接单”。

## 交付序列

1. 统一事件、任务、快照和接力包 Schema；
2. 统一适配器接口和 readback/ACK 状态机；
3. 将现有 mission、session、handoff、artifact 模块接到 `workspace_id`；
4. 实现诊断 Agent、策略进化 Agent 的可恢复任务；
5. 完成跨重启、Token 耗尽、窗口漂移、Agent 离线和冲突注入验收；
6. 再接入更多厂商、A2A 网关和浏览器 MCP provider。

## 成功定义

“启动了唤醒命令”不是成功。成功必须同时具备：原工作区绑定、目标会话唯一、消息可见、同事件 ACK、
产物证据、独立验收和可恢复 checkpoint。任何缺项都应显示为未完成或阻塞。
