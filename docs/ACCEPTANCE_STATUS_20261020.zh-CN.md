# 2026-10-20 工程验收与下一阶段

总体系：红皇后—鲶鱼—创造性破坏。世界领先是愿景，不是本项目已证实的排名或能力事实。

## 已有工程能力

事件信箱、文件监听、提案日志、证据冻结、租约/续租、独立身份约束、可选强制模式、指挥队列路由、旧订单退役与投递前阶段检查。原子发布避免半截正式记录，冲突不覆盖；self-test 连接真实测试子进程和脚本状态演练，可复现、留证据。

## 严格区分三个验收层次

|层次|证据|边界|
|---|---|---|
|组件与故障注入|单元测试、并发重复提案、刷新/发布故障模拟|不是断电测试或跨机器事务|
|本地集成|self-test 的测试进程、日志链和报告|复核等角色为脚本，不是独立 Agent|
|真实宿主协作|原会话消息、归属明确的 ACK、有效认领、实际产物与复核|尚未完成端到端验收|

## 优先路线图

本轮回归曾暴露 Windows campaign-watch 时序用例失败（20 秒内未见 timed_out），单独复跑通过，不能断言已证明具体系统负载根因。实际改进：将多次 Python 启动合并为单进程维护与统一截止时间计算；增加可选 ReadyFile 握手，测试等待 READY 而非固定 sleep。异常可选知识摄取不跳过必需任务截止处理；真实桌面唤醒仍未因此验收。

同时修复 command_memory CLI 的 REMAINDER 参数吞噬：动作名后的 --root/--agent 等现在正常解析，仅 run 接受命令尾部，非 run 拒绝未知参数。覆盖 record 隔离目录及 run 显式 -- 分隔命令测试，防止操作错误协作目录。

Windows 重定向编码亦纳入回归：command_memory JSON 及直接调用 workspace_init 的 JSON 使用 ASCII 安全传输，解码后仍保持原 Unicode 文本；后者可能绕过 CLI main 的 UTF-8 初始化，原先在 unittest 入口会触发 cp1252 编码错误。不能只看 pytest 而忽略另一测试入口。

新增 Windows 远程 CI 首次运行发现四项失败：PAD BuildOnly 错误地要求已安装协议处理器，以及三项路径字符串断言未考虑 Windows RUNNER~1 短路径与规范长路径指向同一目录。修复为仅在真实运行 PAD 前检查协议；测试比较 resolve 后的规范路径。保留全部 Windows 测试，不以跳过或移除平台掩盖失败。修复后仍须再次核对四组 CI 结果。

1. P0：核对跨平台 CI 与可安装制品；发现失败先修复，不用新功能掩盖。
2. P0：仅选两名真实队友、一个低风险任务；固定原会话，验证发送/ACK/认领/证据回传/交接，测试重复事件与断线。
3. P1：关闭前述试点发现的状态同步、取消、认证与租约审计缺口。
4. P1：新机器安装与恢复演练；按具体 provider 验收，不宣称任意机器零配置。
5. P2：引入对照任务，测量正确交付率、重复踩坑率、有效突破成本、人工介入次数；验证红皇后挑战、鲶鱼证伪和创造性破坏是否真正有收益。

生产模式不因 self-test 成功自动启用，不自动扩大权限、预算、并发或外部操作范围。下一阶段应集中闭环验收，而非无限扩充提示词或接口。
