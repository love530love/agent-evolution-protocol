# 协作机制前沿演进蓝图

这不是“再加一个工具”的清单，而是让军团在真实作战中持续变强的基础设施。

## 1. 能力协商协议

Agent 不只声明“我会浏览器”，还要声明版本、覆盖动作、成功率、延迟、证据质量和当前负载。调度器根据任务风险和历史结果选择执行者，并在能力退化时自动降权。

## 2. 数字孪生与动作预演

在真实点击前生成窗口、页面和文件状态的简化孪生；先在沙盒中重放动作，确认定位器、输入框和回读条件，再申请真实执行租约。适合上传、发布和批量操作。

## 3. 故障注入与红队演练

定期模拟空页面、幽灵窗口、过期 ref、网络超时、重复回执、Agent 下线和额度耗尽。系统必须能自动停止、换通道、转交或恢复，而不是只在成功路径上测试。

## 4. 证据重放与可逆执行

所有桌面动作记录为事件流：目标、定位器、输入、前后截图、回读和结果。可在脱机环境重放验证；对可逆操作自动生成撤销计划，对不可逆操作提高证据门槛。

## 5. 自适应资源调度

根据任务价值、剩余额度、Agent 负载、失败概率和截止时间计算优先级。高价值任务集中优势力量，低价值探索使用低成本模型；同一失败签名触发全队暂停，避免集体浪费。

## 6. 记忆蒸馏与经验市场

将成功命令、Windows 特例、浏览器定位器、编译修复和失败签名提炼成可检索经验卡。经验卡必须附环境、版本、证据和失效条件，不能把一次偶然成功当成通用规则。

## 7. 竞争与合作双循环

同一任务允许多个 Agent 产生差异化候选；评测阶段竞争，证据和失败原因阶段共享。鲶鱼角色负责提出反例，仲裁者负责保留异议，主调度器负责选择下一轮投入。

## 8. 人类只处理不可判定事件

系统自动完成发现、分工、唤醒、执行、回访、回表和重试。只有身份验证、授权边界、不可逆高风险决策或证据冲突才升级给人类，并提供最小必要上下文。

## 近期落地顺序

1. 能力协商与历史成功率；
2. 统一动作事件日志和证据重放；
3. 故障注入测试套件；
4. 预算/额度感知调度；
5. 经验卡自动蒸馏与失效检测。
